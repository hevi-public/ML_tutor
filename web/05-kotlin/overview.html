Kotlin in 2026: the 1.9 → 2.4 arc

One story dominates recent Kotlin history: the K2 compiler landed in 2.0 and everything since builds on it. This page is the map — which line is current, which line your build actually uses, and what each release added.

At a glance
  • Current is 2.4.10. Kotlin ships two feature releases a year (June and December-ish) with x.y.20-style tooling updates between. There is no LTS — fixes land in the newest line.
  • Your build's Kotlin is probably not 2.4. Spring Boot's BOM pins its own Kotlin version — 2.3.21 on Boot 4.1 — unless you override kotlin.version or manage the plugin yourself.
  • K2 is the dividing line. 2.0 (May 2024) replaced the compiler frontend; every language feature since exists only there. 1.9 is legacy in the strong sense: unfixed and feature-frozen.
  • Language features stabilise slowly and deliberately — most preview for one or two releases first. What went stable where is on the language page.

The arc

LineReleasedWhat defined it
1.9Jul 2023 The last K1 line. If a codebase is here, the K2 migration is the first move — everything below is unreachable.
2.0May 2024 K2 stable and default: rewritten frontend, one semantic model, JetBrains-measured clean builds up to ~94% faster.
2.1Nov 2024 Preview syntax (guard conditions, non-local break/continue, $$-interpolation). JSpecify nullability violations become errors by default.
2.2Jun 2025 That preview syntax goes stable; context parameters arrive in preview. Interface methods compile to JVM default methods.
2.3Dec 2025 Unused-return-value checker, nested type aliases stable, Java 25 support. The line Spring Boot 4.1 pins (2.3.21).
2.4Jun 2026 Context parameters and explicit backing fields stable; rich errors and collection literals experimental. Java 26 target.

What it replaced

If you maintain a 1.9-era service: the K2 migration is mostly a version bump — the language is the same — but build plugins (KSP, allopen, serialization) must move in the same step, and kapt-heavy builds should migrate processors to KSP while they are at it.

Gotcha: you have three Kotlin versions The Gradle plugin version (your catalog), the version Spring Boot's BOM pins for libraries (kotlin.version property — 2.3.21 on Boot 4.1), and the kotlinx-coroutines version (Boot manages 1.10.2; current standalone is 1.11.0). They are allowed to differ — newer compiler against older stdlib is supported — but when something "works locally", this is the first place to look.
Before 2.0 — for reading old build files

Signs a build predates the K2 era: a kotlin-kapt plugin doing heavy lifting, freeCompilerArgs full of -Xuse-k2 or language-version pins, and CI timings that justify them. None of it is a recommendation — the compiler flags in particular tend to survive long after the reason for them died.
