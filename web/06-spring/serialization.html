Serialization: Jackson 2 → 3

Jackson finally shipped its break (Oct 2025): new packages, an immutable mapper, honest defaults. Boot 4 adopted it as the default — this page is what actually changes in a Kotlin service, and how the two-Jacksons transition period works.

At a glance
  • Boot 4 = Jackson 3 by default (BOM: 3.1.4). A Jackson 2 BOM (2.21.4) stays managed so migrating dependencies resolve consistently.
  • The annotations did not move. @JsonProperty and friends stay at com.fasterxml.jackson.annotation — deliberately, so both lines coexist while libraries migrate.
  • Your @JsonComponent is now @JacksonComponent, and builder customizers target JsonMapper.builder().
  • The clock is running: Framework 7.1 stops auto-detecting Jackson 2; 7.2 drops support. The escape hatches are for landing, not living.

What it replaced

In a Boot app most of these were already overridden to the new values by Boot's defaults — which is why many services notice the flip only in tests that construct a bare ObjectMapper.

Gotcha: the mixed-classpath months A library that hasn't migrated exposes com.fasterxml types in its API — you cannot hand it a tools.jackson mapper. The two lines coexist fine as parallel stacks (that's the design), but a single object graph must be serialized by one of them end-to-end. When a dependency forces Jackson 2, keep it on the managed 2.21.x BOM and isolate it behind its own mapper rather than downgrading the app.

kotlinx.serialization — when instead?

Boot 4 ships a spring-boot-starter-kotlin-serialization: a compile-time, reflection-free alternative that's attractive for pure-Kotlin wire types (and required on platforms without reflection). The trade: no Jackson ecosystem (jOOQ JSON columns, Micrometer, third-party modules all speak Jackson), annotations on every class, and less flexible unknown-shape handling. For a Spring service whose JSON is API payloads, Jackson 3 with the Kotlin module remains the default answer; reach for kotlinx when the types are shared with multiplatform code.

Reading Jackson 2-era configuration

new ObjectMapper() mutated across half a dozen configure(…) calls, JavaTimeModule registered by hand, @JsonComponent serializers, and WRITE_DATES_AS_TIMESTAMPS disabled in every service since 2015. Jackson 3 made most of that ceremony the default behaviour; the remaining intent moves into one builder customizer.
