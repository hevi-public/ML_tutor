Spring Boot

Config & starters

Which starter to name since the Boot 4 renames, and how configuration should look: immutable types bound at startup, profiles for environments, and the handful of properties that changed behaviour recently.

At a glance
  • Starters renamed in 4.0: -web → -webmvc, -web-services → -webservices, OAuth ones gained a security- prefix. Test starters exist per technology (-webmvc-test).
  • Flyway/Liquibase need their own starter now — having the library on the classpath no longer autoconfigures it.
  • Model config as immutable @ConfigurationProperties types; constructor binding is the default. Validate at the edge with jakarta.validation.
  • spring-boot-starter-classic exists for migrations that need the old monolithic classpath — use it to land the upgrade, then delete it.

Do it this way now

// build.gradle.kts — the Boot 4 starter set for this stack
dependencies {
    implementation("org.springframework.boot:spring-boot-starter-webmvc")
    implementation("org.springframework.boot:spring-boot-starter-jooq")
    implementation("org.springframework.boot:spring-boot-starter-flyway")
    implementation("org.springframework.boot:spring-boot-starter-security")
    implementation("org.springframework.boot:spring-boot-starter-actuator")
    testImplementation("org.springframework.boot:spring-boot-starter-webmvc-test")
    testImplementation("org.springframework.boot:spring-boot-starter-jooq-test")
}
// Configuration is a type, registered once
@ConfigurationProperties("app.billing")
@Validated
data class BillingProperties(
    @field:NotBlank val apiKey: String,
    val endpoint: URI,
    val timeout: Duration = Duration.ofSeconds(2),
)

@SpringBootApplication
@ConfigurationPropertiesScan   // finds every @ConfigurationProperties type
class App

What it replaced

Properties worth knowing in 2026

PropertySinceWhat it does
spring.threads.virtual.enabled3.2 Virtual thread per request + virtual task executor (Java 21+). See coroutines page.
logging.structured.format.console3.4 Structured log output: ecs, logstash or gelf.
spring.mvc.apiversion.*4.0 How API versions resolve: header, query param, path segment or media-type param.
spring.jackson.json.read.* / write.*4.0 The relocated Jackson JSON feature toggles (Jackson 3 era).
spring.jackson.use-jackson2-defaults4.0 Migration aid: keep Jackson 2-era serialization behaviour under Jackson 3.
management.opentelemetry.*4.1 OTel tuning; standard OTel env vars are honoured too.
Gotcha: the silent starter miss After a 3.x → 4.0 upgrade, Flyway "stops running" and security "loses" the OAuth client — because the classpath no longer implies the autoconfiguration. Nothing errors; features just don't happen. The migration guide's dependency table is the checklist; run with --debug once and read the autoconfiguration report if something feels absent.
Older idioms you will still read

@Value("${app.billing.timeout}") on scattered fields, mutable setter-bean properties classes, @ConstructorBinding annotations (redundant since Boot 3), and application.properties where the team since moved to YAML. All still function; none is how new config should be written.
