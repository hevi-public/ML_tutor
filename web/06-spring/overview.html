Spring Boot 3 → 4, Framework 7

Boot 4 (Nov 2025) is the biggest release since the jakarta break: Framework 7, Jackson 3 by default, JSpecify null-safety, modular starters and first-class API versioning. This page is the arc, the support clock, and exactly what the 4.1 BOM manages.

At a glance
  • Current is Boot 4.1.0 (June 2026), on Framework 7.0.8 and Security 7.1.0. Runs on Java 17–26; 25 is the LTS to be on.
  • All of 3.x is out of OSS support since 30 June 2026 (3.5 was the last line; commercial support continues). The upgrade target is 4.x — see versions for the clocks.
  • The BOM is the version authority. Boot 4.1 decides Jackson 3.1.4, jOOQ 3.21.5, Kotlin 2.3.21 and friends — override only with a reason you can defend.
  • Migration effort is real but mechanical: renamed starters, removed @MockBean, Jackson 3 types — the migration guide's list, not a rewrite.

What it replaced

Kept in the ledger because you still meet it: any dependency last built for Boot 2 drags javax.* onto the classpath, and the failure modes (NoClassDefFoundError on jakarta types) point everywhere except at the real culprit.

Gotcha: "Boot 4 upgrade" is mostly a Framework 7 upgrade The changes that bite are Framework-level: JSpecify annotations turning sloppy nullness into Kotlin compile errors, Jackson 3 types in signatures, ListenableFuture gone. Read the Boot migration guide first, but budget the time for Framework 7's list — that is where the code edits live.
Boot 2 — for reading old services

javax.* imports, spring.factories autoconfiguration registration, WebSecurityConfigurerAdapter subclasses and @EnableGlobalMethodSecurity date a codebase to the Boot 2 era (out of OSS support since 2023). The 2→3 jump is the expensive one — jakarta plus Java 17 — after which 3.5→4.x is routine.
