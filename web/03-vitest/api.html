Asymmetric matchers

For the parts of a value you do not want to pin down:

expect(saved).toEqual({
  id: expect.any(String),
  name: 'Ada',
  createdAt: expect.any(Date),
  tags: expect.arrayContaining(['admin']),
  meta: expect.objectContaining({ version: 2 }),
});
toBe vs toEqual, once toBe compares identity, so expect({a:1}).toBe({a:1}) fails — two different objects. toEqual compares structure and passes. Use toBe for primitives and when you genuinely mean "the same object".

Mocking

CallDoes
vi.fn(impl?)A mock function
vi.spyOn(obj, 'm')Wraps a method, still calling through
vi.mock('./path')Replaces a whole module. Hoisted above imports
vi.hoisted(fn)Run code before the hoisted vi.mock calls
vi.unmock('./path')Undo a module mock
vi.stubGlobal('fetch', fn)Replace a global

vi.clearAllMocks()Clear recorded calls, keep implementations
vi.resetAllMocks()Clear calls and implementations

Mock function methods

CallDoes
.mockReturnValue(v)Always returns v
.mockReturnValueOnce(v)Next call only. Chainable for a sequence
.mockResolvedValue(v)Returns a resolved promise
.mockRejectedValue(e)Returns a rejected promise
.mockImplementation(fn)Replaces the body
.mock.callsArray of argument arrays
.mock.resultsWhat each call returned or threw
vi.mock is hoisted Calls to vi.mock are moved above every import in the file, so they cannot reference variables declared in the file body — that fails with a confusing "cannot access before initialization". Put the setup inside vi.hoisted(), or build the mock inside the factory.
