Migrations

Most of Angular's breaking changes ship with a schematic that rewrites your code. This is the index of which command does what — and which changes have no command and need a person.

At a glance
  • ng update runs the migrations for the version you are stepping to, automatically. The commands below are for running one on its own — because you skipped it, or want to adopt a pattern before you are forced to.
  • Schematics edit files in place. Run them on a clean working tree so the diff is reviewable, and read that diff: they are good, not infallible, and they cannot see intent.
  • A schematic that rewrites templates will reformat them. Expect a large diff and consider running your formatter in the same commit.

The general shape

SituationCommand
Step to the next Angular major, running its migrations ng update @angular/core @angular/cli
Run migrations only, without changing versions ng update @angular/core --migrate-only --from=21 --to=22
Adopt a pattern early, on your own schedule ng generate @angular/core:<migration-name>
See what a schematic would do without writing files ng generate @angular/core:<name> --dry-run
Gotcha ng update will not skip majors. Going from 19 to 22 is three steps, in order, and each one runs its own migrations. Editing package.json by hand to jump the queue skips every one of them and converts a morning into a fortnight.
