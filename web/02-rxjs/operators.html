RxJS

The operator index

RxJS has around a hundred operators. In an Angular application you will use about fifteen. These are those fifteen, plus the ones worth recognising when you meet them.

The working set
  • Transform: map, switchMap, scan
  • Filter: filter, distinctUntilChanged, take, takeUntilDestroyed
  • Time: debounceTime, throttleTime, delay
  • Combine: combineLatest, withLatestFrom, merge, forkJoin
  • Errors: catchError, retry
  • Side effects: tap

Time

OperatorDoesUse for
debounceTime(ms)Emits only after a quiet gapSearch-as-you-type: wait until they stop typing
throttleTime(ms)Emits at most once per intervalScroll and resize handlers
auditTime(ms)Emits the last value of each intervalLike throttle, but you want the newest not the oldest
delay(ms)Shifts everything laterRarely what you want in production
timeout(ms)Errors if nothing arrives in timeGuarding a slow endpoint

Combination

OperatorEmits whenUse for
combineLatest([a$, b$])Any source emits — once all have emitted at least once"Recompute whenever any filter changes"
withLatestFrom(b$)The primary source emits, sampling b"On submit, take the current form value"
forkJoin([a$, b$])All sources complete — emits their last valuesPromise.all for Observables
merge(a$, b$)Any source emits, interleavedSeveral event sources, one handler
concat(a$, b$)In order, each after the previous completesSequenced work
race(a$, b$)Only the first to emit; the rest are unsubscribedFastest-wins
startWith(v)Emits v immediately, then the sourceInitial state before the first real value
combineLatest waits for everyone It emits nothing at all until every source has produced at least one value. One source that never emits means silence, and it looks exactly like a bug elsewhere. startWith() on each input is the usual fix.
forkJoin needs completion It waits for every source to complete. Give it a Subject, an interval, or a valueChanges stream and it will wait forever. HTTP calls complete, so forkJoin is right for those and wrong for almost everything else.

Side effects and utility

OperatorDoes
tap({ next, error, complete })Runs a side effect without changing the stream. Logging, debugging
finalize(fn)Runs on completion, error or unsubscribe. Turning off a spinner
toArray()Collects everything into one array on completion
shareReplay({bufferSize:1, refCount:true})Shares one run and replays the last value
