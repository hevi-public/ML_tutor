Versions & support windows

Which version is current, when yours stops being supported, and what landed in each release. Dates come from the package registries — npm for the front end, Maven Central and services.gradle.org for the JVM tools — so they are the real publish dates rather than the blog-post dates.

At a glance
  • Angular ships twice a year, roughly May and November. Each major gets 6 months of active support, then 12 months of LTS — so a version is done 18 months after release.
  • Spring Boot ships a minor every six months, and each minor gets about 13 months of open-source patches. 3.5 was the last 3.x line and left OSS support in June 2026.
  • PostgreSQL ships a major every September and supports it for five years — the only clock here measured in years, and the one people forget until the November it expires.
  • Kotlin and Gradle have no support windows — fixes land in the newest line only. Your effective Kotlin version is often the one Spring Boot's BOM pins (2.3.21 on Boot 4.1), not the newest (2.4.10).
  • RxJS 7.8 is the answer. RxJS 8 has been in alpha since 2025 and is deliberately on hold until Observable is standardised on the web platform. Do not plan around a date.
  • Vitest majors land roughly yearly. Angular pins a compatible range through @angular/build, so in an Angular repo you usually upgrade Vitest by upgrading Angular.
  • pnpm 11 moved its configuration. If you upgrade from 10, settings in package.json and .npmrc stop being read — see the pnpm section.
  • Jackson is two parallel lines now. New work happens on 3.x (tools.jackson.*); 2.x continues in maintenance. Spring Boot 4 defaults to Jackson 3.

Are you still supported?

Three of these tools have a published clock. Angular: 18 months per major. Spring Boot: ~13 months of open-source support per minor — the Support column below tracks the OSS window; commercial support runs years longer. PostgreSQL: five years per major. A version marked out of support receives no further patches, including security patches.

The short version, today Angular 19 left support in May 2026 — 20/21 are in LTS, 22 is active. Spring Boot 3.x is entirely out of OSS support since June 2026: the upgrade target is 4.x. PostgreSQL 13 died in November 2025, and 14 goes this November — if you are on 14, the upgrade is a security matter, not a features matter.

Upgrading

Angular

Angular upgrades are one major at a time — ng update will refuse to skip. Each step runs the schematics that rewrite your code for that version's changes, which is why skipping majors by editing package.json by hand costs far more than it saves.

What you wantCommand
See what an upgrade would do, without doing it ng update
Step to the next major ng update @angular/core @angular/cli
Step to a specific major ng update @angular/core@21 @angular/cli@21
Re-run a single migration you skipped ng update @angular/core --migrate-only --from=21 --to=22

The JVM stack

There is no ng update here — versions live in your build, so upgrades are edits to the build. The order that works: Gradle first (the wrapper is per-repo), then the Spring Boot plugin version (its BOM moves Framework, Security, Jackson and jOOQ together), then whatever the BOM does not manage.

What you wantHow
Upgrade Gradle for this repository ./gradlew wrapper --gradle-version 9.7.0
See what is stopping the next Gradle major ./gradlew build --warning-mode all
Upgrade Spring Boot (and its whole BOM) bump org.springframework.boot in the version catalog, then read the migration guide's list for that minor
Upgrade Kotlin bump the kotlin("jvm") plugin in the catalog — but check what Boot's BOM pins first
Upgrade PostgreSQL a major pg_upgrade (in-place, fast) or logical replication (near-zero downtime); since 18, planner statistics survive the jump

The interactive, version-to-version checklist is on the official update guide, and the per-version migration schematics get their own page in this reference.
