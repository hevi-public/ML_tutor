Angular

Templates

Control flow is part of the template language now. No imports, proper type narrowing, and a track expression the compiler insists on.

At a glance
  • @if / @else if / @else, @for / @empty, @switch — built in, nothing to import.
  • @for requires track. This is deliberate: the missing trackBy was Angular's most common performance bug.
  • @let names a value without needing a conditional to hang it on.
  • @defer lazy-loads a block and everything only it uses.
  • The old structural directives still work and are not deprecated.

Do it this way now

@let user = currentUser();
@let unread = notifications().filter(n => !n.read).length;

@if (user) {
  <h2>Welcome back, {{ user.name }}</h2>
} @else if (loading()) {
  <app-spinner />
} @else {
  <a routerLink="/login">Sign in</a>
}

@for (item of items(); track item.id; let i = $index, isLast = $last) {
  <li [class.last]="isLast">{{ i + 1 }}. {{ item.label }}</li>
} @empty {
  <li class="muted">Nothing here yet.</li>
}

@switch (status()) {
  @case ('draft')     { <badge-draft /> }
  @case ('published') { <badge-live /> }
  @default            { <badge-unknown /> }
}

@defer (on viewport) {
  <sales-chart [data]="data()" />
} @placeholder (minimum 300ms) {
  <div class="skeleton"></div>
} @error {
  <p>Chart failed to load.</p>
}

What changed

The schematic rewrites templates wholesale, so expect a very large diff on the first run — and run your formatter in the same commit, because indentation shifts throughout. It is a syntax change with no behaviour change, which makes it one of the safer large diffs you will review.

@for and track

track tells Angular how to recognise the same item across renders. Get it wrong and Angular destroys and recreates DOM nodes it could have kept — losing focus, scroll position, input state and animations along the way.

SituationTrack by
Items with a stable idtrack item.id
Primitives (strings, numbers) that are uniquetrack item
A list that is only ever replaced wholesaletrack $index
Items with no id, order never changestrack $index
Gotcha: track $index on a reorderable list Index-tracking says "the item at position 3 is the same item it was before". Sort or filter the list and every row's contents change under a DOM node that Angular thinks is unchanged — so a focused input keeps focus while its value jumps to a different record. Use a real id whenever items can move.

The implicit variables available inside @for: $index, $first, $last, $even, $odd, $count. Alias them with let i = $index when nesting loops, since the inner $index otherwise shadows the outer one.

@defer triggers

TriggerFires whenGood for
on idleThe browser is idle (the default)Anything below the fold
on viewportThe placeholder scrolls into viewCharts, maps, comment threads
on interactionClick or keydown on the placeholderEditors, rich inputs
on hoverPointer enters the placeholderPreviews, popovers
on timer(2s)After a delayLow-priority widgets
when cond()The expression becomes trueAnything you control
prefetch on …Fetches early, renders laterPair with a later render trigger
Gotcha: @defer only splits what is used only inside it If a component in a deferred block is also imported by the surrounding template, it is already in the main bundle and nothing is saved. Check the build output rather than assuming — a @defer that defers nothing is easy to write and invisible without looking.

Type narrowing

A genuine advantage over the directives: @if narrows types the way TypeScript does. Inside @if (user()), the compiler knows user() is not null — no !, no ?.. The old *ngIf narrowed only through its as alias, which is part of why that idiom was everywhere.

Before v17 — structural directives, for reading old code 
<h2 *ngIf="user$ | async as user; else signedOut">
  Welcome back, {{ user.name }}
</h2>
<ng-template #signedOut>
  <a routerLink="/login">Sign in</a>
</ng-template>

<li *ngFor="let item of items; trackBy: trackById; let i = index">
  {{ i + 1 }}. {{ item.label }}
</li>

<ng-container [ngSwitch]="status">
  <badge-draft *ngSwitchCase="'draft'"></badge-draft>
  <badge-unknown *ngSwitchDefault></badge-unknown>
</ng-container>

Three things to notice, because they explain the shape of old templates: else needed a named <ng-template> declared elsewhere; trackBy took a method on the component rather than an expression; and CommonModule had to be imported or none of it worked at all — silently, since an unknown attribute is not an error.

All of this still compiles in v22. None of it is deprecated.
