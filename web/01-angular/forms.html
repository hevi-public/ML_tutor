Forms

Signal Forms went stable in v22. The headline change: your model is the form, rather than something you keep in sync with one.

At a glance
  • form(modelSignal, schema) returns a field tree mirroring your model's shape.
  • It does not copy your data — writing through a field writes the model signal you passed in.
  • Every node exposes value(), valid(), invalid(), touched(), dirty(), errors(), pending(), disabled(), readonly(), hidden(), submitting().
  • Validation is declared against typed paths, so renaming a field is a compile error rather than a silently dead rule.
  • Imports come from @angular/forms/signals. Reactive forms are untouched and not deprecated.

Do it this way now

import { signal } from '@angular/core';
import { form, required, email, minLength, disabled, submit }
  from '@angular/forms/signals';

export class ProfilePage {
  // Your model. An ordinary writable signal — nothing form-specific about it.
  profile = signal({ name: '', email: '', newsletter: false });

  profileForm = form(this.profile, (path) => {
    required(path.name, { message: 'We need a name.' });
    minLength(path.name, 2);

    required(path.email);
    email(path.email);

    // Rules can be conditional on the model's own values.
    disabled(path.newsletter, ({ value }) => !value().email);
  });

  async save() {
    await submit(this.profileForm, {
      action: async (form) => {
        await this.api.saveProfile(form().value());
      },
    });
  }
}
<input [field]="profileForm.name" />
@if (profileForm.name().touched() && profileForm.name().invalid()) {
  <p class="error">{{ profileForm.name().errors()[0]?.message }}</p>
}

<button [disabled]="profileForm().invalid() || profileForm().submitting()"
        (click)="save()">Save</button>

What changed

The "does not copy" property is the one to hold on to. With reactive forms you had a model and a FormGroup, and a meaningful fraction of form code existed purely to move data between them — patchValue on load, getRawValue on save, and a subscription in between. Signal Forms delete that category of code, because there is only ever one copy of the data.

Migrating gradually

There is no schematic, and for a large form you would not want one — but the migration is designed to be partial. @angular/forms/signals/compat exists so a signal form and a reactive form can coexist while you move field groups across one at a time, rather than rewriting a 40-field form in one commit.

A sensible order: new forms use Signal Forms from the start; existing forms move when you are already changing them for another reason. A working reactive form is not a defect.

Gotcha: the field is a function, and so is its state profileForm.name is the field; profileForm.name() is its state; profileForm.name().value() is the value. Two sets of parentheses before you reach data takes some getting used to, and forgetting one produces a type error that reads oddly until the pattern clicks.
Gotcha: the schema callback is not reactive The function you pass to form() runs once to declare rules. The rules are reactive — a disabled() predicate re-evaluates as values change — but the callback body itself does not re-run. Reading a signal directly in it, rather than inside a rule's predicate, captures a value at setup time and quietly never updates.
Reactive forms — for the code you already have 
profileForm = new FormGroup({
  name: new FormControl('', [Validators.required, Validators.minLength(2)]),
  email: new FormControl('', [Validators.required, Validators.email]),
});

ngOnInit() {
  this.api.loadProfile().subscribe(p => this.profileForm.patchValue(p));
}

save() {
  if (this.profileForm.invalid) return;
  this.api.saveProfile(this.profileForm.getRawValue()).subscribe();
}

Two long-standing sharp edges, for context on why the API changed: form.get('name') took a string, so a typo or a rename gave you null at runtime rather than a compile error; and value excluded disabled controls while getRawValue() included them, which is a data-loss bug people hit repeatedly.

Typed forms in v14 fixed the worst of the typing. None of this is deprecated.
