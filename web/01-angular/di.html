Dependency injection

The most mechanical of the modern-Angular migrations, and the one that unlocked the rest: once inject() worked outside constructors, guards and interceptors could stop being classes.

At a glance
  • inject(Thing) as a field initialiser, not a constructor parameter.
  • @Service() instead of @Injectable({ providedIn: 'root' }).
  • provideAppInitializer() instead of the APP_INITIALIZER token.
  • Guards, resolvers and interceptors are plain functions that call inject().
  • inject() only works in an injection context — that constraint is the one thing here worth understanding properly.

Do it this way now

import { Service, inject, InjectionToken } from '@angular/core';
import { HttpClient } from '@angular/common/http';

@Service()
export class UserStore {
  private http = inject(HttpClient);
  private config = inject(APP_CONFIG);

  load(id: string) {
    return this.http.get<User>(`${this.config.apiUrl}/users/${id}`);
  }
}

// A token for anything that is not a class.
export const APP_CONFIG = new InjectionToken<AppConfig>('APP_CONFIG', {
  providedIn: 'root',
  factory: () => ({ apiUrl: '/api' }),
});

// Reusable logic that needs DI, without being a service.
export function usePageTitle(title: string) {
  const titleService = inject(Title);
  titleService.setTitle(title);
}

What changed

The reason this matters more than it looks: a constructor parameter can only be injected into a class being constructed. inject() works in any injection context, which is what makes a functional guard, a functional interceptor, or a shared useSomething() helper possible at all.

@Injectable() is not deprecated and still works. @Service() is the shorter spelling of what almost every service wanted.

The injection context

This is the one rule that produces confusing runtime errors, so it is worth stating precisely. inject() works only while Angular knows which injector you belong to. That is true in exactly these places:

WorksDoes not work
Field initialisers of a component / directive / service Inside ngOnInit or any lifecycle hook
The constructor body Inside a setTimeout or promise callback
A factory in InjectionToken or a provider Inside a method called later
Functional guards, resolvers and interceptors Inside an RxJS operator callback
Inside runInInjectionContext(injector, fn) Anywhere else
Gotcha: NG0203 "inject() must be called from an injection context" almost always means the call moved into a callback or a lifecycle hook. Two fixes: hoist the inject() to a field initialiser (usually right), or capture const injector = inject(Injector) up front and later wrap the work in runInInjectionContext(injector, () => …) (for the genuinely deferred cases).

Functional guards and interceptors

The clearest payoff of inject(). A guard used to be a class implementing an interface, registered by type; now it is a function.

// guard
export const authGuard: CanActivateFn = (route, state) => {
  const auth = inject(AuthService);
  const router = inject(Router);
  return auth.isLoggedIn() || router.createUrlTree(['/login']);
};

// interceptor
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).token();
  return next(token
    ? req.clone({ setHeaders: { Authorization: `Bearer ${token}` } })
    : req);
};

// wiring
bootstrapApplication(App, {
  providers: [provideHttpClient(withInterceptors([authInterceptor]))],
});
Before v14 — constructor injection and class guards 
@Injectable({ providedIn: 'root' })
export class UserStore {
  constructor(
    private http: HttpClient,
    @Inject(APP_CONFIG) private config: AppConfig,
    @Optional() @SkipSelf() parent?: UserStore,
  ) {}
}

@Injectable()
export class AuthGuard implements CanActivate {
  constructor(private auth: AuthService, private router: Router) {}
  canActivate() { return this.auth.isLoggedIn(); }
}

Two costs, both real: subclassing meant repeating the whole parameter list in every super() call, and every piece of DI-using logic had to be a class because that was the only place injection happened. Constructor injection still works and is not deprecated — it is simply more typing for less reach.
