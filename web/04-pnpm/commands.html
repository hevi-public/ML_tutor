What npm has no answer for

CommandDoes
pnpm why pkgShows every path that pulls a package in. The fastest way to answer "why do I have three copies of this?"
pnpm patch pkgOpens an editable copy; pnpm patch-commit saves a patch reapplied on every install. Fixing a dependency bug without forking
pnpm licenses listEvery dependency's licence — for compliance reviews
pnpm deploy <dir>Copies a workspace package plus its dependencies into a standalone directory. Docker images without the whole monorepo
pnpm sbomGenerates a software bill of materials (v11)
pnpm peers checkReports unmet or conflicting peer dependencies (v11)
pnpm cleanRemoves generated artefacts (v11)
pnpm store pruneDeletes store entries nothing references any more
pnpm store pathWhere the store actually is
pnpm env use --global 22Installs and switches Node versions — no separate version manager
pnpm why is underused Duplicate versions, a mysterious transitive dependency, a security advisory against something you have never heard of — pnpm why answers all three in one line, and prints an actual tree rather than npm's flat listing.

Running scripts

CommandDoes
pnpm buildRuns the build script
pnpm -r buildRuns it in every workspace package, in dependency order
pnpm -r --parallel devAll at once, ignoring order
pnpm --filter web buildOnly in the web package
pnpm exec tsc --noEmitRuns a local binary
pnpm dlx @angular/cli new appRuns a package without installing it
pnpm run --sequential a bSeveral scripts in order
Gotcha: a script named like a pnpm command pnpm build works because there is no built-in build. A script called add, install, update, link or ci is shadowed by the real command — use pnpm run install explicitly.

Pinning the version

Different pnpm versions can resolve differently, so a team should agree on one. The packageManager field does that, and Corepack (or pnpm's own runtime handling) enforces it:

// package.json
{
  "packageManager": "pnpm@11.17.0"
}

Note that v11 removed managePackageManagerVersions, packageManagerStrict and packageManagerStrictVersion; the pmOnFail setting covers what all three did.
