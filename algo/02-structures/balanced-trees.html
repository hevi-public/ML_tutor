Balanced trees: bushiness by force

The last page ended with sorted input turning a BST into a chain. This page feeds the same poison to a tree that fights back — rotating itself bushy after every insert — and the O(log n) promise becomes unconditional.

Before you start Binary search trees, especially the degeneration demo — this page is its antidote.

The idea

The BST rule constrains order but not shape. Balanced trees add a second rule about shape, and one repair tool. The tool is the rotation: a local re-pointing of two or three references that lifts a child above its parent without breaking the BST order rule — the middle key ends up on top, smaller stuff left, bigger stuff right, exactly as before, but the heights have shifted. It's O(1) — no data moves, just pointers.

AVL trees keep the strictest shape rule: at every node, the two subtree heights differ by at most 1. Every insert walks back up checking; a violation triggers one or two rotations, and balance is restored — the tree can never drift further than one rotation's reach out of shape. Red-black trees (the one in most standard libraries) enforce a looser rule via node colors — never two reds in a row, equal black-count on every root-to-leaf path — which bounds height at ~2 log n while doing fewer repair rotations on average. Same idea, tuned differently: AVL flatter (faster lookups), red-black cheaper to update.

Where you'll meet this

Every ordered container in a standard library is one of these — C++ std::map, Java TreeMap, .NET SortedDictionary are red-black trees; kernel schedulers (Linux CFS ran on a red-black tree for years) and epoll timers too. And the disk-shaped descendant is bigger than all of them: the B-tree generalizes "rotate to stay shallow" into "keep nodes fat so the tree is 3–4 levels tall", which is why your database index finds one row in a billion with three page reads. Unit 9's storage-engines page picks that story up.

The details (open as much as you like)

A rotation, in slow motion

Right rotation at node y with left child x: x rises, y becomes x's right child, and x's old right subtree (everything between x and y in value!) becomes y's new left subtree. Three pointer writes. The in-order sequence — left-x-middle-y-right — is untouched, which is the whole point: rotations change heights while provably preserving order. Every balancing scheme (AVL, red-black, splay, treap) is just a different policy for when to apply this same tool.

Show the math — why the AVL rule forces log height

Let N(h) be the fewest nodes an AVL tree of height h can have. The stingiest tree has one subtree of height h−1 and one of h−2 (the rule's limit), so N(h) = 1 + N(h−1) + N(h−2) — Fibonacci in disguise. Since Fibonacci grows exponentially (≈ φⁿ), node count grows exponentially in height, so height grows logarithmically in node count: h ≤ 1.44 log₂(n). The shape rule is local and cheap; the height bound it buys is global and unconditional. Red-black's rule bounds height at 2 log₂(n+1) by a similar counting argument on black nodes.

Which balanced tree should you actually reach for?

In practice: the one your library gives you (almost always red-black), and only after asking whether you need ordering at all — a hash map is simpler and faster when you don't. Read-heavy with rare writes? AVL's flatter shape wins lookups. Everything-on-disk? B-tree, always — the branching factor is set by the page size, not by binary-vs-not. The exotic cousins (splay trees: recently-used keys float to the top; treaps: randomized balance) are unit-11 material.

The code

// The demo's rebalancing core (assets/js/algo/structures.js). After the
// ordinary BST descent, each node on the way back up checks its balance:
const balance = height(node.left) - height(node.right);
if (balance > 1) {                       // left side too tall
  if (height(left.left) < height(left.right))
    node.left = rotate(node.left, "left");     // zig-zag: straighten first
  return rotate(node, "right");                // then lift the left child
}
if (balance < -1) { /* mirror image */ }
// A rotation is three pointer writes — order preserved, heights repaired.
