Storage engines: where the data finally lives

Under every database sits one of two families. One keeps data sorted in place and edits pages on disk — the B-tree, ordered-tree thinking scaled to storage. The other never edits anything: it appends, sorts in memory, flushes immutable files, and cleans up later — the LSM tree, whose secret engine is merge sort. The choice is a bargain about reads, writes, and space — and this page closes unit 9 by pricing it.

Before you start Balanced trees, merge sort, and Bloom filters — all three report for duty here.

The idea

B-trees (Postgres, MySQL/InnoDB, SQLite): unit 2's balanced tree with a disk-shaped constant — nodes are 4–16 KB pages holding hundreds of keys each, so the tree is fat and shallow: a billion rows in 3–4 levels, and a point read costs 3–4 page fetches (fewer with the top levels cached). Writes edit pages in place; a full page splits — the self-balancing act, now with disk I/O. Reads and range scans are superb; every small write pays read-modify-write on whole pages.

LSM trees (RocksDB, Cassandra, LevelDB, and the engines under many analytics/streaming stores): writes go to an in-memory sorted buffer (memtable) — O(log n), no disk read. When full, it flushes as an immutable sorted file (SSTable) — sequential I/O, the kind disks love. Reads must now consult memtable + several files (newest wins) — kept sane by per-file Bloom filters — and background compaction merge-sorts overlapping files into fewer, bigger ones, discarding overwritten versions. The bargain in one line: B-trees pay at write time to keep one sorted place; LSMs pay after write time (compaction) to have made writes sequential.

Where you'll meet this

Choosing a database IS choosing this bargain: OLTP with hot updates and range queries → B-tree engines; write-heavy event streams, time series, message queues, and anything ingest-bound → LSM. The vocabulary decodes ops dashboards: "write stall" = compaction fell behind; "space amp" = old versions awaiting compaction; "read amp" = files consulted per lookup. LLM-era systems sit on both: vector databases store their HNSW graphs and payloads over these engines (several are literally RocksDB inside), conversation/memory stores for agents are LSM-shaped ingest, and checkpoint/artifact stores care about exactly the sequential-write-throughput property LSMs optimize. The whole unit in one object: hashing (Bloom), sorting (merge), trees (B/memtable), amortization (compaction), all load-bearing at once.

The details (open as much as you like)

The three amplifications — the bargain, quantified

Write amplification: bytes physically written ÷ bytes logically written. B-trees: a 100-byte update rewrites a 16 KB page (and maybe splits). LSMs: each byte is rewritten once per compaction level — typically 10–30× lifetime, but sequential, which disks (and SSD lifetimes) vastly prefer over random page edits. Read amplification: structures consulted per lookup — B-tree: tree depth; LSM: memtable + files, minus everything Bloom filters exclude. Space amplification: LSMs carry dead versions until compaction reclaims them. No engine wins all three — the RUM conjecture (read/update/memory) says you pick two, which is why compaction strategies (leveled vs tiered) are themselves a read-vs-write dial inside the LSM family. Amortized analysis from unit 1 is the honest lens: LSM writes are cheap on average because compaction debt is paid later — and "write stalls" are what the debt collector looks like.

The code

// The demo's exact LSM core, events elided:
function write(key, value) {
  memtable.set(key, value);                     // sorted in memory, no disk read
  if (memtable.size >= CAP) {
    sstables.push([...memtable.entries()].sort());   // flush: sequential write
    memtable.clear();
  }
}
function read(key) {
  if (memtable.has(key)) return memtable.get(key);   // newest first
  for (const file of newestFirst(sstables)) {
    if (!file.bloom.mightContain(key)) continue;     // certain-no: skip file
    const hit = binarySearch(file, key);             // unit 3, on disk
    if (hit) return hit;
  }
}
function compact() {                            // merge sort, unit 3, as a daemon
  sstables = [kWayMerge(sstables)];             // newest version wins; dead
}                                               // versions dropped — space reclaimed
