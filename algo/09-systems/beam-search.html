Beam search: exploring an exponential tree on a budget

Generating a sentence is walking an implicit tree where every node is a partial text and every edge appends one token — a branching factor of fifty thousand, a depth of hundreds. Exhaustive search is off by dozens of orders of magnitude; pure greed takes the best next token and gets trapped by it. Beam search is the standing compromise: keep the k best partial paths, extend them all, keep the k best again.

Before you start States-as-nodes (this is that page's biggest graph), best-first search, and tokens as the edges.

The idea

Score a partial sequence by its total log-probability (sums, not products — unit 1's log toolkit keeping numbers sane). Greedy decoding (k = 1) commits to the single best token each step; the classic failure is a locally-great token leading somewhere globally poor — the garden path. Beam search widens the commitment: at each step, extend all k survivors by every candidate token, score the extensions, keep the top k sequences. It's A*'s frontier with a hard size cap and no admissible heuristic — which surrenders the optimality guarantee (the best full sequence can fall off the beam early) in exchange for a fixed compute budget: k× the cost of greedy, tunable.

Where you'll meet this

Machine translation and speech recognition shipped on beam search for a decade (it still runs Whisper's decoder and most production MT). Chat LLMs mostly use sampling instead (temperature, top-p) — beams optimize for the single most probable text, which reads repetitive and "safe" in open-ended generation; sampling trades probability mass for diversity. But the beam mindset — k survivors under a budget — reappears wherever LLM systems search: self- consistency (sample k reasoning chains, vote), tree-of-thought agents (k plans kept alive, weakest pruned), and code generators keeping k candidates for the test suite to judge. Constrained decoding composes directly: intersect each step's candidates with a trie of grammatically legal tokens (unit 7) and the beam only ever holds valid JSON.

The details (open as much as you like)

Beam search in the strategy taxonomy

Place it on unit 6's map: greedy explores one path; A* explores best-first with a completeness guarantee (admissible h, unbounded frontier); exhaustive search explores everything; beam search is best-first with a fixed-size frontier — a heuristic without guarantees, chosen because the state space is 50,000-ary and guarantees are unaffordable. Known limitations are part of the craft: beams collapse (all k survivors sharing a prefix — diversity penalties exist), and raw log-prob sums favor short sequences (fixed by length normalization — dividing by lengthᵅ, a knob every MT system exposes). The professional stance the whole course has rehearsed: know which guarantee you gave up, and measure what it costs on your workload.

The code

// The demo's exact loop, events elided:
function beamSearch(model, k, steps) {
  let beams = [{ seq: ["<s>"], score: 0 }];
  for (let t = 0; t < steps; t++) {
    const candidates = [];
    for (const b of beams) {
      for (const [tok, logp] of model.next(b.seq)) {   // every continuation
        candidates.push({ seq: [...b.seq, tok], score: b.score + logp });
      }
    }
    candidates.sort((a, b) => b.score - a.score);
    beams = candidates.slice(0, k);      // survival of the k fittest SEQUENCES
  }
  return beams[0];                       // best complete path that survived
}
