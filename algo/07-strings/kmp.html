KMP: the pattern that remembers itself

The naive search's sin: on a mismatch it forgets everything the last few comparisons revealed and re-reads text characters. Knuth, Morris and Pratt's 1977 cure: preprocess the pattern so that after any mismatch, it already knows the furthest it can safely jump — the text pointer never moves backward, guaranteeing O(n + m) on every input, adversarial ones included.

Before you start The naive baseline, so the waste being eliminated is vivid. The failure function is honest DP — unit 6 pays off here.

The idea

Suppose you've matched abab of pattern ababc and the next text character mismatches. Naive slides one and re-compares from scratch. But look at what's already known: the text just contained abab. If the pattern shifts by 2, its prefix ab lines up with the suffix ab of what matched — those two characters are guaranteed to match without looking. So: shift 2, resume comparing at pattern position 2. No text re-reads.

The precomputation is the failure function: fail[i] = the length of the longest proper prefix of pat[0…i] that is also a suffix of it. In plain English: after matching i+1 characters and failing, how much of a head start does the pattern still have? It depends only on the pattern — computed once in O(m), by the pattern searching itself.

Where you'll meet this

KMP's guarantee — linear time, no text backtracking — makes it the tool for streaming: network intrusion detection matching signatures on packets it can't rewind, protocol scanners, and any match-on-a-pipe situation. Its multi-pattern generalization, Aho-Corasick (a trie with failure links — two pages composing), scans for thousands of keywords in one pass and runs inside spam filters, virus scanners and content moderation. The failure-function idea — "index how a sequence overlaps itself" — reappears in Z-arrays, rolling-checksum sync (rsync), and tandem-repeat finders in genomics.

The details (open as much as you like)

Why the total is O(n) — an amortized argument

The search loop looks nested — the inner while can fire several fallbacks per text character. The clean accounting is unit 1's amortized analysis: let k be the matched-prefix length. Each text character increments k at most once; each while-iteration strictly decreases k. A counter that only grows n times can only shrink n times: at most 2n loop iterations total, regardless of pattern or adversary. The same argument, run on the pattern against itself, gives O(m) for building fail[]. Guaranteed linear — the property that made this a landmark, and the property the naive method's average-case luck can't offer.

Reading fail[] as dynamic programming

fail[i] is defined in terms of smaller subproblems: to extend, try k = fail[i−1]; if pat[i] ≠ pat[k], fall back to fail[k−1], and so on — each candidate is a previously computed answer, chained. It's memoized recursion over "longest border of each prefix", built left to right in dependency order: bottom-up DP by any other name. The lesson worth exporting: preprocessing an input into a self-referential index is DP applied to the pattern rather than the query — the same design that unit 9's tokenizer tries and suffix structures scale up.

The code

// The demo's exact code (assets/js/algo/strings.js), events elided:
function kmpSearch(text, pat) {
  const fail = buildFailure(pat);       // O(m): pattern vs itself
  const hits = [];
  let k = 0;                            // chars of pattern currently matched
  for (let i = 0; i < text.length; i++) {   // i NEVER decreases
    while (k > 0 && text[i] !== pat[k]) k = fail[k - 1];  // reuse overlap
    if (text[i] === pat[k]) k++;
    if (k === pat.length) {             // full match
      hits.push(i - k + 1);
      k = fail[k - 1];                  // keep going — overlaps allowed
    }
  }
  return hits;
}
