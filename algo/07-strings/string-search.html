Substring search: the honest baseline

Find every occurrence of a pattern in a text — the query under Ctrl-F, grep, log scanning, and DNA matching. The obvious algorithm slides the pattern one position at a time and compares. It's fine, mostly. This short unit is about the word "mostly" — and about the beautiful machinery invented for the cases where it isn't.

Before you start Nothing beyond Big-O. This unit is self-contained; its ideas feed unit 9's tokenizers.

The idea

Text of length n, pattern of length m. At each of the n−m+1 alignments, compare left to right; mismatch → slide the pattern one step right and start comparing from scratch. Worst case O(n·m): text aaaaaaaab, pattern aaab — every alignment marches almost to the end of the pattern before failing.

But note what the worst case needs: long stretches where text and pattern almost-match repeatedly. On typical text with a typical alphabet, mismatches arrive within a character or two and the naive method averages out near O(n) — which is why it's genuinely what many standard libraries use for short patterns, sometimes with a first-character skip loop. Baseline first, cleverness when measured necessary: the whole course's engineering stance, in miniature.

Where you'll meet this

grep on a log file, String.includes, editor find, intrusion-detection systems scanning packets for signatures, plagiarism and duplicate detection, read-alignment in genomics (where n is three billion and m is a few hundred — the O(n·m) question stops being academic). Real engines mix strategies: memchr-style vectorized first-byte scans, Boyer-Moore-family skips for long patterns, automata for multi-pattern sets. Knowing the naive baseline's actual (good!) average case is what lets you read those engines' trade-offs instead of cargo-culting them.

The details (open as much as you like)

Average vs worst — where the n·m actually hides

For random text over alphabet size σ, the expected comparisons per alignment form a geometric series: 1 + 1/σ + 1/σ² + … ≤ σ/(σ−1) — barely more than one. Total: O(n), for free. The pathologies need self-similar data: long runs, repeated motifs — precisely what DNA (σ = 4, highly repetitive), binary protocol dumps, and adversarial inputs look like. The security note is real: quadratic blowup on attacker-chosen strings is a denial-of-service primitive (the same family as ReDoS from the backtracking page), which is why "worst case doesn't matter" needs the follow-up question "who chooses the input?".

The code

// The demo's exact code (assets/js/algo/strings.js), events elided:
function naiveSearch(text, pat) {
  const hits = [];
  for (let s = 0; s + pat.length <= text.length; s++) {  // each alignment
    let ok = true;
    for (let i = 0; i < pat.length; i++) {
      if (text[s + i] !== pat[i]) { ok = false; break; } // abort, slide by 1
    }
    if (ok) hits.push(s);
  }
  return hits;
}
