Approximation: provably good, never perfect

NP-hardness kills fast exact optimization, not fast good optimization. An approximation algorithm runs in polynomial time and ships with a certificate of quality: "my answer is at most twice the optimum — for every input, guaranteed." That last clause separates this page from heuristics: a guarantee you can put in an SLA versus a vibe you hope holds up.

Before you start P and NP (why we're settling), greedy (the machinery we'll reuse — this time with proofs about how wrong it can be).

The idea

An algorithm is a ρ-approximation if for every input its answer is within a factor ρ of the true optimum. The craft is bounding your distance from a number you can't compute — always via a lower bound: find something easy to compute that the optimum itself cannot beat, then show your answer is within a factor of that. Both demos below use the trick; watch for it.

Watch it run

Vertex cover, 2-approximation: repeatedly grab any uncovered edge and take both endpoints. The grabbed edges share no endpoints (a matching), and every cover — the optimum included — needs at least one endpoint from each, so OPT ≥ (edges grabbed) and ours = 2 × (edges grabbed) ≤ 2 × OPT. Where you'll meet this

Set-cover greedy (ln n guarantee) is the shape of monitoring-probe placement, test-suite minimization and ad targeting; bin-packing first-fit (≤ 1.7 × OPT) is memory allocators and shipping-container logistics; k-center clustering's 2-approximation is data-center placement. Routing products layer heuristics (2-opt, or-opt) on top of construction algorithms like nearest neighbor. And the vocabulary matters commercially: "within 2× guaranteed" and "usually near-optimal in benchmarks" are different promises with different lawyers.

The details (open as much as you like)

The 2-approximation proof, spelled out

Let M be the set of edges the algorithm grabbed. (1) M is a matching: once an edge is grabbed, both endpoints are covered, so no later grabbed edge can touch them. (2) Any vertex cover C must contain ≥ 1 endpoint of every edge in M — those are edges, and C covers all edges. Since M's edges are disjoint, those endpoints are distinct: |C| ≥ |M|, and in particular OPT ≥ |M|. (3) Our cover has exactly 2|M| nodes. Chain them: ours = 2|M| ≤ 2·OPT. Note what we never needed: OPT's actual value. The matching is the computable stand-in — every approximation proof has one.

Sharper is provably hard: beating factor 1.36 for vertex cover is NP-hard, and under the (widely believed) unique games conjecture, 2 − ε is out of reach — this simple algorithm may be optimal among fast ones.

Metric TSP: the MST trick and Christofides

When distances obey the triangle inequality: the minimum spanning tree (unit 5!) costs ≤ OPT, because deleting one edge of the optimal tour leaves a spanning tree that can't beat the MST. Walk around the MST (each edge twice: cost ≤ 2·OPT), then shortcut repeated visits — shortcuts can't lengthen a metric walk. Result: a 2-approximation from a data structure you already own. Christofides (1976) fixes up the walk with a minimum matching on odd-degree vertices for 1.5×, which stood unimproved for 44 years (the 2020 improvement shaved off a factor of about 10⁻³⁶ — theory moves in mysterious increments). Without the triangle inequality, no constant factor is achievable unless P=NP: approximating general TSP well would let you decide Hamiltonian-cycle exactly.

The code

// Vertex cover 2-approximation — the entire algorithm:
function approxVertexCover(edges) {
  const cover = new Set();
  for (const [u, v] of edges) {
    if (!cover.has(u) && !cover.has(v)) {   // an uncovered edge…
      cover.add(u); cover.add(v);           // …take BOTH ends
    }
  }
  return cover;                              // ≤ 2 × optimal. Proven, not hoped.
}
