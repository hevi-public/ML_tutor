Bit tricks: sets, masks and the machine's native tongue

An integer is 32 tiny booleans standing in a row, and the processor operates on all of them in one cycle. That makes integers the fastest set implementation you will ever get — the trick unit 6's bitmask DP leaned on — plus a small canon of one-liners (clear the lowest bit, test for a power of two) that show up in real allocators, schedulers and interviews. This page is the decoder ring.

Before you start Nothing beyond binary notation. If you're arriving from bitmask DP, the "bits as sets" table below is the promised payoff.

The idea

Number the members of a small universe 0..31. Any subset becomes one integer: bit i set ⇔ element i present. Set operations become single instructions — union is |, intersection is &, complement is ~, symmetric difference is ^ — and "for each subset" becomes counting from 0 to 2ⁿ−1, which is exactly how unit 6's traveling-salesman DP enumerated its states. The second family of tricks exploits two's-complement arithmetic: n & (n−1) clears the lowest set bit (subtracting 1 flips the trailing run), and n & −n isolates it. Everything else on this page is a corollary of those two sentences.

Where you'll meet this

Feature flags and permission systems (Unix's rwxr-xr-- is a 9-bit mask; every ORM's flags & CAN_EDIT), CPU sets and scheduler affinity masks in the kernel, chess engines (bitboards: one 64-bit integer per piece type, move generation as shifts), memory allocators rounding to powers of two ((n + 7) & ~7 aligns to 8), network masks (CIDR is literally "count the leading ones"), compression and serialization formats packing booleans, unit 9's Bloom filter setting its k bits, and HyperLogLog counting leading zeros. Modern CPUs expose popcount and count-leading-zeros as single instructions — JavaScript's Math.clz32 is the latter.

The details (open as much as you like)

Why n & (n−1) clears the lowest set bit

Write n as …x100…0 — some prefix x, then the lowest set bit, then trailing zeros. Subtracting 1 borrows through the zeros: n−1 = …x011…1 — the prefix survives, the lowest set bit falls to 0, the trailing zeros flip to 1s. AND the two and the disagreeing suffix vanishes: …x000…0. Corollaries: a power of two has exactly one set bit, so n & (n−1) === 0 tests for it (mind n = 0); Kernighan's popcount loops "clear lowest bit, count" and runs once per set bit, not per bit — the demo shows the loop's trace. Similarly −n in two's complement is ~n + 1, which flips everything above the lowest set bit but not it — so n & −n keeps exactly that bit.

Iterating subsets of a mask — bitmask DP's inner loop

The idiom for (let s = m; s; s = (s − 1) & m) visits every non-empty subset s of mask m, in decreasing order: subtracting 1 rolls the subset's odometer downward and the & m snaps it back inside the universe. Across all m of size n this totals 3ⁿ steps (each element is in m-only, in s, or out — three states), the bound that governs set-cover-style DPs. One more staple: enumerating supersets is s = (s + 1) | m. These two lines are most of what "expert" bitmask DP adds to unit 6.

The code

// Bits as sets — the entire API, one operator each:
const has    = (set, i) => (set >>> i) & 1;
const add    = (set, i) => set | (1 << i);
const remove = (set, i) => set & ~(1 << i);
const union = (a, b) => a | b, intersect = (a, b) => a & b, diff = (a, b) => a & ~b;

function popcount(n) {              // Kernighan: one iteration per SET bit
  let c = 0;
  while (n) { n &= n - 1; c++; }    // clear lowest set bit
  return c;
}
const isPowerOfTwo = (n) => n > 0 && (n & (n - 1)) === 0;
const lowestBit    = (n) => n & -n;
const alignUp8     = (n) => (n + 7) & ~7;   // allocator staple
