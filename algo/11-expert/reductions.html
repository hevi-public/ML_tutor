Reductions: proving hardness by translation

A reduction is a compiler between problems: rewrite any instance of problem A as an instance of problem B, such that B's answer is A's answer. It's how one hard problem (SAT) became thousands ("NP-complete" is a family tree of reductions) — and, run in the other direction, it's the most practical trick on this page: encoding your problem into a solver somebody else already built.

Before you start P, NP and NP-completeness — this page is how the "thousands of problems" claim there actually works.

The idea

Write A ≤ B ("A reduces to B") when any instance of A can be transformed, in polynomial time, into an instance of B whose answer matches. Two consequences, and the whole game is keeping their directions straight:

Hardness flows forward: if A is known hard and A ≤ B, then B is at least as hard — a fast B-solver would give a fast A-solver through the translation. To prove your problem hard, you reduce a known NP-complete problem to it. (Reducing your problem to SAT proves nothing about yours — everything in NP reduces to SAT.)

Easiness flows backward: if B has a good solver and A ≤ B, you can solve A by translating. This direction ships software: encode into SAT/ILP and let an industrial solver do the search.

Watch it run

The textbook example, live: Vertex Cover ≤ Independent Set — and back, because the transformation is its own inverse. A set S covers every edge exactly when its complement V∖S contains no edge. Click nodes to build a set; the two verdicts below can never disagree:

This graph's minimum vertex cover has 5 nodes, so its maximum independent set has 8 − 5 = 3 — the two numbers are one fact wearing two costumes. An optimizer for either problem solves the other at zero extra cost; a hardness proof for either condemns both.

Where you'll meet this

The shipping direction daily: dependency resolution encoded as SAT (Conda, Cargo, Debian's apt all run solvers), scheduling encoded as ILP, Kubernetes-style bin-packing encoded as constraints, hardware verification encoded as SAT (model checking), Sudoku-as-SAT as the classic party trick. The proving direction at design reviews: unit 5's matching page already showed a benign one (assignment ≤ max-flow), and "our feature is graph coloring in disguise" is the professional way to say no to an optimal-realtime-scheduler ticket. Recognizing your problem as a costume on a known one — easy or hard — is the fastest architecture decision you'll ever make.

The details (open as much as you like)

A real gadget: 3-SAT ≤ Independent Set, sketched honestly

Reductions between unlike-looking problems run on gadgets — small structures encoding one problem's parts in the other's vocabulary. For a 3-SAT formula with m clauses: build a triangle of three nodes per clause (one per literal); connect every pair of contradictory literals (x and ¬x) across triangles. A triangle admits at most one chosen node, so an independent set of size m must pick exactly one literal per clause — and the contradiction edges forbid picking both x and ¬x. Therefore an independent set of size m exists exactly when the formula is satisfiable: pick each triangle's true literal. Formula → graph is polynomial, and the answer carries over. That's the whole craft: triangles enforce "choose one", edges enforce "not both".

Karp's 21, and what "complete" buys you

Cook made SAT the first domino (1971); Karp's 1972 paper knocked down 21 more — clique, vertex cover, Hamiltonian cycle, partition, coloring — each by reduction from an earlier one, and the family has grown into the thousands since. The payoff of "NP-complete" being a single equivalence class under reduction: results transfer. One SAT-solver improvement speeds up every encoded problem; one polynomial algorithm for any member would collapse them all. It's why industrial effort concentrated on SAT/ILP solvers rather than a thousand bespoke exact engines — and why encoding into them is such a reliable move.

// The demo's entire "theorem": one predicate is the other, complemented.
const isVertexCover = (edges, S) =>
  edges.every(([u, v]) => S.has(u) || S.has(v));

const isIndependentSet = (edges, S) =>
  edges.every(([u, v]) => !(S.has(u) && S.has(v)));
