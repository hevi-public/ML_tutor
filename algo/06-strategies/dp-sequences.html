Unit 6 · Design strategies

DP on sequences: the algorithm inside diff

Fib was DP with training wheels — one dimension, one recurrence term. Sequence problems are where the recipe earns its keep: define what a table cell means, write how it follows from its neighbors, fill in dependency order. Edit distance — the algorithm under every diff view you've ever read — is the flagship.

Before you start The 4-step DP recipe. Everything here is that recipe, with the table grown to two dimensions.

The idea

Edit distance: the minimum number of single-character inserts, deletes, and substitutions turning string a into string b. Recipe step 1, the sentence: d[i][j] = the edit distance between the first i characters of a and the first j characters of b. Step 2, the recurrence — look at the last characters:

d[i][j] = \min\big(d[i{-}1][j] + 1,\; d[i][j{-}1] + 1,\; d[i{-}1][j{-}1] + [a_i \ne b_j]\big)

In plain English: delete a's last character, or insert b's, or line the two last characters up — free if they match, one substitution if not. Three neighbors, one min.

Step 3: (m+1)(n+1) cells × O(1) each = O(mn). Step 4: fill rows top-to-bottom — every cell's three dependencies sit up and left. The answer is the bottom-right cell, and walking the choices backward from it recovers the actual edit script: that traceback path is literally the diff.

Where you'll meet this

git diff and every code-review pane run LCS/edit-distance machinery (Myers' algorithm — same DP, cleverer frontier). Spell checkers rank corrections by edit distance; fuzzy search (fzf, database LEVENSHTEIN) is this table; DNA sequence alignment (Needleman-Wunsch/Smith-Waterman) is this exact recurrence with biological scoring — computed at genome scale. Speech-recognition scoring (word error rate) is edit distance on words. And evaluation harnesses for LLM outputs lean on edit-distance-family metrics whenever "how different are these two texts?" needs a number.

The details (open as much as you like)

LIS — same recipe, different sentence

Longest increasing subsequence: in [3, 1, 8, 2, 5, 4, 7, 6], find the longest subsequence that climbs — here length 4 (e.g. 1, 2, 5, 7). The sentence: len[i] = length of the longest increasing subsequence ending exactly at index i. Recurrence: len[i] = 1 + max(len[j]) over all j < i with arr[j] < arr[i]. O(n²), traceback recovers the chain. The pattern to notice: "ending exactly at i" is the standard dodge when a subproblem needs a firm anchor — the same dodge that defines many DP sentences. (A binary-search refinement gets O(n log n) — patience sorting — worth knowing exists.)

Space: you rarely need the whole table

Edit distance's recurrence reads only the previous row — so two rows suffice: O(min(m, n)) memory instead of O(mn), which is the difference between diffing chromosomes in RAM or not. The catch: row-recycling destroys the traceback (the path needs the full table). Hirschberg's trick gets both — divide & conquer to find where the optimal path crosses the middle row, then recurse on the two halves: full alignment in linear space, O(mn) time. A beautiful example of two strategies (D&C + DP) composing, and it ships in bioinformatics tools for exactly the RAM reason.

The code

// The demo's exact code (assets/js/algo/dp.js), events elided:
function editDistance(a, b) {
  const d = table(a.length + 1, b.length + 1);
  for (let i = 0; i <= a.length; i++) d[i][0] = i;   // delete everything
  for (let j = 0; j <= b.length; j++) d[0][j] = j;   // insert everything
  for (let i = 1; i <= a.length; i++) {
    for (let j = 1; j <= b.length; j++) {
      const cost = a[i - 1] === b[j - 1] ? 0 : 1;    // match is free
      d[i][j] = Math.min(
        d[i - 1][j] + 1,        // delete a[i]
        d[i][j - 1] + 1,        // insert b[j]
        d[i - 1][j - 1] + cost, // substitute (or match)
      );
    }
  }
  return d[a.length][b.length];  // traceback from here = the edit script
}
