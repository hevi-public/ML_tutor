Huffman coding: greed's masterpiece

Give frequent symbols short codes and rare symbols long ones, and text shrinks. In 1951 David Huffman, dodging a final exam by solving the term problem instead, found the optimal way — a greedy algorithm of almost insulting simplicity: merge the two rarest things; repeat. It's been inside essentially every compressor since.

Before you start The exchange argument and unit 2's heap — "give me the two smallest, repeatedly" is a priority queue's job description.

The idea

A prefix code assigns each symbol a bit string such that no code is a prefix of another — which is exactly the property that makes decoding unambiguous, and exactly what "symbols live at the leaves of a binary tree" guarantees: left = 0, right = 1, the path is the code. The cost of a tree is \sum_c f(c) \cdot \text{depth}(c) — in plain English: total bits used = each symbol's frequency times the length of its code. Optimal compression = the cheapest tree.

Huffman's move: the two lowest-frequency symbols should be the deepest nodes — so make them siblings at the bottom, merge them into a pseudo-symbol carrying their combined frequency, and recurse on the smaller alphabet. A heap makes each merge O(log n); n−1 merges build the whole tree.

Where you'll meet this

DEFLATE — the compressor inside gzip, zlib, PNG, and ZIP — is LZ77 + Huffman; JPEG and MP3 entropy-code with it; HTTP/2 compresses headers with a standardized static Huffman table (HPACK). When you enable gzip on an API response, this tree gets built for your bytes. The deeper lineage: "frequent things should be cheap to say" is the same force that shapes LLM tokenizers — BPE (unit 9) is a greedy merge-the-most-frequent-pair loop, Huffman's mirror image, trading optimality for streamability. And arithmetic/ANS coding (zstd's entropy stage) is Huffman's fractional-bit successor.

The details (open as much as you like)

Show the proof — the sibling exchange

Lemma: some optimal tree has the two rarest symbols x, y as sibling leaves at maximum depth. Exchange: take any optimal tree; let a, b be siblings at its deepest level. If x isn't already there, swap x with a: cost changes by (f(a) − f(x)) · (depth(x) − depth(a)) ≤ 0, since f(x) ≤ f(a) and a was at least as deep. Swap y with b likewise. Still optimal, now with x, y as bottom siblings. Then induction: merging x, y into one pseudo-symbol of frequency f(x)+f(y) turns any tree for the smaller alphabet into one for the original with extra cost exactly f(x)+f(y) — a constant — so optimizing the smaller problem optimizes the original. Greedy merge = optimal, all the way up. ∎

Note the two-part shape: an exchange establishing the greedy choice is safe, then induction on the reduced problem. That's the full greedy-proof template, reusable verbatim.

How good is it? Entropy, and the fractional-bit gap

Shannon's source coding theorem sets the floor: no prefix code beats the entropy H = -\sum_c p(c) \log_2 p(c) bits per symbol — in plain English, the true information content of the distribution. Huffman is optimal among whole-bit-per-symbol codes and lands within 1 bit of H. The gap bites when one symbol dominates (p = 0.99 still costs a full bit per occurrence); arithmetic coding and ANS close it by spreading symbols across fractional bits — that's why zstd's entropy stage outperforms plain Huffman on skewed data. Engineering summary: Huffman when simplicity and speed rule; fractional coders when the distribution is lopsided and percentage points matter.

The code

// The demo's exact code (assets/js/algo/dp.js), events elided:
function huffman(freqs) {
  let forest = freqs.map((x) => ({ ch: x.ch, f: x.f }));
  while (forest.length > 1) {
    forest.sort((a, b) => a.f - b.f);        // a heap in production: O(log n)
    const a = forest.shift(), b = forest.shift();   // two rarest
    forest.push({ f: a.f + b.f, left: a, right: b }); // merge, re-enter pool
  }
  return forest[0];                          // the tree; paths are the codes
}
