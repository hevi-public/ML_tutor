Greedy: commit early, never look back — with a license

Take the best-looking option, lock it in, repeat. It's the cheapest strategy there is — one pass, no memory of roads not taken — and it's usually wrong. The craft is recognizing the problems where it's provably right, and the proof pattern is always the same trick: the exchange argument.

Before you start The strategy map. You've already seen licensed greed win three times: Dijkstra, Kruskal/Prim — this page extracts what those proofs shared.

The idea

The showcase problem: interval scheduling. One meeting room, many requested meetings with start/end times; accept the most meetings possible. Plausible greeds disagree — shortest first? fewest conflicts first? earliest start? The right answer: earliest finish time first. Sort by end time; accept whatever doesn't overlap the last accepted meeting.

Why that key and not the others? Finishing early is the choice that constrains the future least — it leaves the room free soonest. That intuition becomes a proof below, and its shape — "any optimal solution can be exchanged, one step at a time, into the greedy one without getting worse" — is the license every correct greedy algorithm carries.

Where you'll meet this

Licensed greed runs infrastructure: earliest-deadline-first in real-time schedulers, Huffman in every compressor (next page), Dijkstra in every router, Kruskal in network design. Unlicensed greed runs incidents: bin-packing VMs largest-first, rate limiters admitting whoever asks first, cache eviction by gut feeling — all greedy heuristics that are fine until the workload finds the case where local best ≠ global best. The professional move isn't avoiding greed; it's knowing which of your greeds hold a proof and which hold a hope.

The details (open as much as you like)

Show the proof — the exchange argument

Claim: earliest-finish-first accepts a maximum number of intervals. Let G = g₁, g₂, … be greedy's picks in order and OPT = o₁, o₂, … any optimal schedule, both sorted by finish time. Step 1 (greedy stays ahead): by induction, finish(gᵢ) ≤ finish(oᵢ) for every i. Base: g₁ has the earliest finish of all intervals. Step: if finish(gᵢ₋₁) ≤ finish(oᵢ₋₁), then oᵢ — which starts after finish(oᵢ₋₁) — was also compatible after gᵢ₋₁, so greedy had it available and chose something finishing no later. Step 2: if OPT had more intervals than G, the next one o|G|+1 starts after finish(o|G|) ≥ … wait — by step 1, finish(g|G|) ≤ finish(o|G|), so o|G|+1 would also have been compatible with greedy's last pick, and greedy would have taken something. Contradiction: greedy only stops when nothing fits. ∎

"Greedy stays ahead" and "exchange" are the two standard license forms. If you can't sketch one for your greedy idea, treat the idea as a heuristic and say so in the design doc.

The counterexample gallery — plausible greeds that fail

Shortest interval first: a short meeting bridging two long compatible ones kills both — greedy 1, optimal 2. Earliest start first: one all-day meeting starting at 9:00 blocks five short ones — greedy 1, optimal 5. Fewest conflicts first: constructible failure with a diamond of conflicts (greedy 3, optimal 4 — CLRS exercise). The moral: intuitions about "obviously best" keys are cheap; small counterexamples are cheaper. Hunt for a counterexample before hunting for a proof — five minutes of adversarial doodling settles most greedy proposals.

The code

// The demo's exact code (assets/js/algo/dp.js), events elided:
function intervalScheduling(intervals) {
  const sorted = intervals.slice().sort((a, b) => a.end - b.end);  // THE key
  const accepted = [];
  let lastEnd = -Infinity;
  for (const iv of sorted) {
    if (iv.start >= lastEnd) {     // fits after everything accepted so far
      accepted.push(iv);
      lastEnd = iv.end;            // commit — never reconsidered
    }
  }
  return accepted;
}
