Quickselect: the k-th smallest, without the sort

"What's the median?" doesn't require sorting — sorting answers a thousand questions when you asked one. Ask for less, pay less: expected linear time, from a one-line change to quicksort.

Before you start Quicksort — specifically what a partition guarantees about the pivot's final position.

The idea

Recall the partition's receipt: after one linear pass, the pivot sits at its final sorted index i, smaller values left, larger right. Quicksort recursed into both sides. But if you only want the k-th smallest, the receipt tells you which single side holds it: i = k means the pivot itself is the answer; i < k means it's somewhere right; i > k, left. Recurse into one side and throw the other away unexamined.

That one change collapses the cost. Quicksort's balanced recurrence 2T(n/2) + n gave n log n; quickselect's is T(n/2) + n — and the geometric series n + n/2 + n/4 + … from the math toolkit sums below 2n. Expected linear, with the same fine print as quicksort: bad pivots on adversarial input give n², and the same coin-flip fix applies.

Where you'll meet this

Percentiles are the native language of operations: p50/p95/p99 latency dashboards, SLO burn alerts, trimmed means in metrics pipelines. Exact percentiles over big batches are quickselect's job (numpy.partition is literally introselect); streaming approximations (t-digest, HDR histograms) exist because even linear re-scans get expensive at telemetry scale — but they're calibrated against this exact algorithm. Also here: "top k%" cutoffs in ranking and the median-based robust statistics that survive outliers where averages lie.

Show the math — why one side means linear

Expected work: a random pivot leaves the surviving side ≤ ¾n with probability ½, so the expected surviving size shrinks geometrically: levels cost about n + (¾)n + (¾)²n + … ≤ 4n = O(n). The contrast with quicksort is exactly "one child vs two" in the recursion tree — the difference between the tree's total weight and one root-to-leaf path's. Same partition, different tree shape, different complexity class.

Guaranteed linear: median-of-medians, and why nobody ships it

The 1973 median-of-medians algorithm picks the pivot by taking medians of groups of five, recursively — guaranteeing a 30/70-or-better split and worst-case O(n). It's a landmark proof that selection is fundamentally linear… with constants so heavy that practice uses randomized quickselect (or introselect: quickselect with a median-of-medians parachute, mirroring introsort). The pattern to keep: an elegant guarantee can lose to a coin flip plus a fallback — and the hybrid gets both.

  if (i === k) return a[i];      // the k-th smallest, found without sorting
  if (i < k) lo = i + 1;         // answer is right of i — left side abandoned

}
