Unit 3 · Sorting & searching

The elementary sorts: three ways to spend n²

Selection, insertion, bubble — all quadratic, all "obsolete", and all still worth an hour: they're where sorting's key ideas (invariants, stability, adaptivity) are easiest to see, and one of them secretly ships inside every production sort you use.

Before you start The staircase sum from the math toolkit — all three of these pay it.

The idea

Each maintains a sorted region and grows it, with a different invariant:

Selection sort: "the first i slots hold the i smallest values, in final position." Scan the rest for the minimum, swap it in. Always exactly the staircase of comparisons, even on sorted input — but the fewest swaps of any sort (n−1), which once mattered when writes were expensive.

Insertion sort: "the first i slots are sorted (not necessarily final)." Take the next value, slide it left to its place. On random input: the staircase. On nearly-sorted input: almost nothing — each element moves only as far as it's out of place. This adaptivity is why insertion sort survives inside grown-up sorts.

Bubble sort: sweep, swapping adjacent inversions; repeat. Same staircase, more swaps, no compensating virtue — its job on this site is to be the honest baseline the others beat.

Insertion on nearly-sorted input hugs the straight line — linear when the data is almost in order. That's why real-world sorts (Timsort, pdqsort, your language's built-in) hand small or nearly-sorted runs to insertion sort: production data is nearly-sorted far more often than chance would suggest (appended logs, resorted lists, merged feeds).

Where you'll meet this

Directly: insertion sort runs inside Timsort (Python, Java, and JavaScript's Array.sort in several engines) for runs under ~32 elements, and inside C++'s introsort below similar thresholds — so most sorts your programs perform end their recursion in this page. Conceptually: "keep a sorted prefix and insert into it" is how you maintain a sorted list under streaming inserts, and "count the swaps bubble sort would make" is exactly the inversions metric used to measure how out-of-order a feed or ranking is.

The details (open as much as you like)

Stability — the property that decides real arguments

A sort is stable if equal keys keep their original relative order. Sort orders by amount, then stably by date: rows with the same date remain amount-ordered — multi-key sorting by chaining simple sorts. Insertion and bubble are stable; selection (as written) is not — the long-distance swap can leapfrog equal keys. Stability is also the difference between "sorted the invoices" and "sorted the invoices, scrambling same-day order" — a bug class that surfaces in UIs and reports, not in unit tests with distinct keys.

Show the math — inversions price insertion sort exactly

An inversion is a pair out of order (i < j but a[i] > a[j]). Insertion sort's slides = the inversion count exactly: each adjacent swap fixes precisely one inversion. Shuffled input has ~n²/4 inversions on average (each pair 50/50) — quadratic. K-sorted input (each element ≤ k slots from home) has ≤ nk — linear for small k. One number, both behaviours explained. Bubble sort's swaps equal the same count; it just spends more comparisons finding them.

The code

// Insertion sort — the one that earns its keep (assets/js/algo/sorts.js).
function* insertionSort(a) {
  for (let i = 1; i < a.length; i++) {
    const value = a[i];
    let j = i - 1;
    while (j >= 0) {
      yield { type: "compare", i: j, j: i };
      if (a[j] <= value) break;          // found its place — adaptive exit
      a[j + 1] = a[j];                   // slide one slot right
      yield { type: "set", i: j + 1, value: a[j] };
      j--;
    }
    a[j + 1] = value;
    yield { type: "set", i: j + 1, value };
  }
}
