Unit 8 · Visualisation

Drawing DAGs: make the flow read like text

A dependency graph drawn by physics is a shrug — arrows point everywhere. But a DAG has a story direction, and Sugiyama's method (1981) commits the whole drawing to it: every edge flows the same way, work reads top-to-bottom like a page. It's the layout inside Graphviz's dot, and therefore inside half the architecture diagrams ever committed to a wiki.

Before you start Topological sort — Sugiyama's first phase IS it — and force layout as the contrast.

The idea

Three phases, each a real algorithm from this course:

  1. Layering — assign each node a row such that every edge points strictly downward. Longest-path layering does it with unit 4's Kahn traversal: your layer = 1 + your latest-finishing prerequisite. (Edges spanning several rows get invisible dummy nodes so later phases can treat all edges as one-row hops.)
  2. Crossing reduction — within each row, choose a left-to-right order minimizing edge crossings. Exact minimization is NP-hard even for two rows, so the workhorse is the barycenter heuristic: repeatedly sort each row by the average position of each node's neighbors in the row above, sweeping down and up until it stops improving.
  3. Coordinates — space nodes within rows, straighten long edge chains, balance parents over children (tidy-tree instincts return).

Where you'll meet this

Graphviz dot — the default renderer for compiler IRs, state machines, and dependency graphs — is Sugiyama end to end, so every terraform graph | dot and pprof callgraph you've read used these three phases. CI/CD pipeline views (GitHub Actions, GitLab), Airflow/Dagster DAG pages, dbt lineage graphs, Spark query plans, and LangGraph-style agent-pipeline visualizers all draw layered DAGs — orchestration tooling without Sugiyama would be illegible. When your team's architecture diagram "flows down", this algorithm chose what sits where.

The details (open as much as you like)

Why crossings are THE enemy, and what barycenter buys

Eye-tracking studies agree with intuition: edge crossings are the single strongest predictor of graph-reading errors — each crossing is a chance to follow the wrong wire. Minimizing them exactly is NP-hard (even between just two fixed rows — one-sided crossing minimization), so this is the course's hardness theory paying practical rent: know it's NP-hard, reach for a heuristic without guilt. Barycenter — sit each node at its parents' average — is startlingly effective (typically within a few percent of optimal), cheap, and stable. The demo's sweeps usually stop changing after two passes; dot adds a median variant and local swap polishing.

Choosing between the unit's layouts — the decision table

Hierarchy, single root → tidy tree. Directed flow / dependencies → Sugiyama layers. Undirected relationships, communities → force. Dense graph (hairball) → adjacency matrix (next page). Part-of-whole with sizes → treemap (next page). The question that picks: what should the reader's eye follow? Depth → tree. Order of execution → layers. Nearness → force. Existence/absence of links en masse → matrix. Budgets → treemap. This table is the unit's takeaway artifact — pin it near wherever dashboards get designed.

// Phase 2 — barycenter sweeps:
for (sweep of 1..3)

    sortRowBy(node => average(position of node's parents in row above))
