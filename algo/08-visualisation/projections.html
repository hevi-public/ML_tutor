Projections: drawing what has no x and y

Embeddings — the coordinates LLM systems think in — live in hundreds of dimensions. A screen has two. Every "map of our documents" you've seen is a projection: an algorithm that chose, out of infinitely many flattenings, one that (it hopes) keeps what matters. Knowing what each family keeps — and quietly destroys — is the unit's parting skill.

Before you start Encodings. If you've met vectors and dot products anywhere (the ML track's linear-algebra pages count), you're ahead; the demo needs neither.

The idea

The naive projection: pick two of the original axes and drop the rest. Cheap, faithful to the chosen pair — and blind to structure living in the discarded dimensions; two clusters separated along a dropped axis land exactly on top of each other. PCA (principal component analysis) fixes the arbitrariness: it rotates the cloud to find the two orthogonal directions along which the data spreads most, and projects onto those. Linear, deterministic, fast — and honest in a precise sense: on-screen distances are true distances' shadows, only ever shrunk, never invented.

The famous nonlinear family — t-SNE and UMAP — asks a different question: not "preserve global spread" but "keep each point's neighbors next to it", letting the map warp globally to make local neighborhoods crisp. That's what draws those satisfying cluster islands of embedding atlases — at the price that between-island distances and island sizes mean little, and hyperparameters can manufacture or merge clusters. Powerful, standard, and to be read like a caricature: excellent likeness, deliberate distortion.

Where you'll meet this

Embedding atlases of document stores and support tickets ("clusters = topics"), model-debugging views in TensorBoard-style tools, single-cell genomics maps, and every conference slide showing LLM tokens as a galaxy — overwhelmingly t-SNE/UMAP pictures. Production caveats travel with them: retrieval quality lives in the ORIGINAL space (unit 9's vector search never touches the 2-D map), the map is diagnostic only; and cluster count/shape can be hyperparameter artifacts — rerun with different perplexity before believing a story. PCA earns daily keep more quietly: dimensionality reduction before clustering, whitening features, and compressing embeddings for cheaper ANN indexes.

The details (open as much as you like)

PCA in one paragraph of honest math

Center the data; its covariance matrix records how dimensions co-vary. PCA's components are that matrix's eigenvectors, ordered by eigenvalue — equivalently, the directions maximizing projected variance. Each eigenvalue's share of the total is the variance that component explains — the demo's caption quotes it, and it's the honesty meter: two components explaining 85% mean the flat picture is a good shadow; 30% means most structure was flattened away, whatever the picture seems to show. (This demo finds the top components by power iteration — multiply, normalize, repeat — unit 9 territory: it's the same idea PageRank runs on.)

Reading a t-SNE/UMAP map without being fooled

Narrated, not simulated — the algorithms are gradient-descent optimizations beyond this page's demo budget. The reading rules: (1) trust membership — points sharing an island are genuinely similar; (2) distrust island sizes (t-SNE expands dense clusters), distances between islands (mostly meaningless), and apparent density; (3) rerun with different perplexity/neighbors before reporting cluster counts; (4) never compute anything downstream on the 2-D coordinates — cluster and retrieve in the original space. Treat the map as a brilliant, unreliable narrator.

The code

// This page's exact demo code — PCA via power iteration:
function topComponent(X) {                  // X: centered n×d data
  let v = randomUnit(d);
  for (let it = 0; it < 60; it++) {
    let w = new Array(d).fill(0);           // w = Covariance · v, done as
    for (const row of X) {                  //   Σ (row·v) row  — no d×d
      const s = dot(row, v);                //   matrix ever materialized
      for (let j = 0; j < d; j++) w[j] += s * row[j];
    }
    v = normalize(w);                       // multiply, normalize, repeat
  }
  return v;                                 // converges to the top eigenvector
}
// 2nd component: subtract each row's projection on v, run again.
