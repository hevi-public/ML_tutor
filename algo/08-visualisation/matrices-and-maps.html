Unit 8 · Visualisation

When node-link fails: matrices, treemaps, bundling

Dots-and-lines drawings degrade with density — past a few hundred edges they're hairballs, and no layout algorithm can save an encoding that has run out of room. The fixes change the encoding itself: draw the adjacency matrix, draw areas instead of nodes, or route edges in bundles like cable ties.

Before you start Adjacency matrices — the storage format is about to become a picture — and tree layouts.

The idea: the matrix as image

Unit 4 stored a graph as a |V|×|V| grid; render each cell as a pixel and the storage is the visualization. No crossings — ever, by construction — and density becomes a feature: a 500-node near-complete graph is an unreadable hairball as node-link but a perfectly legible dark square as a matrix. The price: paths become invisible (following a→b→c means jumping between cells), and everything depends on row order — the same matrix looks like noise or like block-diagonal structure depending on how rows are permuted. Seriation (finding the revealing order) is its own algorithmic field; a cheap, good trick is ordering rows by cluster or by BFS discovery order.

The idea: treemaps

For hierarchies where size is the question — disk usage, budgets, market caps — the treemap nests rectangles: each node's area is proportional to its value, children tile their parent. The layout algorithm decides the tiling: slice-and-dice (alternate horizontal/vertical cuts — simple, but thin slivers) versus squarified (greedily pack rows keeping aspect ratios near 1 — the industry default, and another licensed-enough greedy). Where you'll meet this

Matrix views: correlation heatmaps in every notebook, sparsity plots of large systems, service-to-service traffic grids, and — centrally for the LLM era — attention heatmaps, which are exactly token-to-token adjacency matrices, read for block and diagonal structure. Treemaps: WinDirStat/ncdu-style disk explorers, bundle-size analyzers (webpack-bundle-analyzer), finance heat-tiles. Edge bundling (below) powers legible airline maps and software-dependency wheels. Choosing among them is the previous page's decision table in action.

Edge bundling, honestly

Not simulated on this page — described. When a node-link view must survive thousands of edges, bundling routes edges with similar start/end regions along shared curved highways (hierarchical bundling routes along the hierarchy; force-directed bundling lets edges attract each other). The gain: flows between regions become visible as thick cables. The loss — say it out loud in reviews: individual edges become untraceable, and bundles can imply connections that don't exist (two edges sharing a highway look related). Bundling is an aggregation, and like all aggregations it trades item-level truth for population-level legibility.

The code

// Squarified treemap core (this page's exact demo code): lay a row of
// children along the short side while it improves the worst aspect ratio.
function squarify(children, rect) {
  const row = [];
  while (children.length) {
    const next = children[0];
    if (!row.length || worstRatio([...row, next], rect) <= worstRatio(row, rect)) {
      row.push(children.shift());        // adding improves (or starts) the row
    } else {
      layoutRow(row, rect);              // row is as square as it gets — fix it
      rect = remaining(rect, row);       // recurse into the leftover space
      row.length = 0;
    }
  }
  layoutRow(row, rect);
}
