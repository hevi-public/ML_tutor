Bellman-Ford: shortest paths that survive negative prices

Sometimes an edge pays you: a currency conversion with a favorable rate, a subsidized route, an action with a reward. Dijkstra's greedy commitment is illegal here. Bellman-Ford trades the cleverness for patience — relax everything, repeatedly — and gets two things back: correctness under negative weights, and a detector for the one situation where "shortest" stops meaning anything.

Before you start Dijkstra, especially the proof layer — this page is what grows back after that proof loses non-negativity.

The idea

Keep the same tentative prices d(v). But make no commitments: in each round, sweep the entire edge list and relax every edge that offers an improvement. After one round, every shortest path of 1 edge is correct; after two rounds, every path of 2 edges; after |V| - 1 rounds, every possible simple path length is covered — done. Cost: O(|V|·|E|), the price of refusing to guess.

Then one extra round as a tripwire. A simple shortest path can't have more than |V|−1 edges — so if a sweep still finds an improvement, some price is being lowered by going in circles: a negative cycle is reachable, a loop whose total weight is below zero. Walk it forever, "cost" plummets without bound — the question "what's the shortest path?" has no answer, and Bellman-Ford is the algorithm that can say so honestly.

Where you'll meet this

Currency arbitrage is the famous one: model conversion rates as edge weights of −log(rate), and a negative cycle IS an arbitrage loop — trading around it multiplies money. Bellman-Ford is literally an arbitrage detector. Distance-vector routing protocols (RIP) are distributed Bellman-Ford: each router repeatedly relaxes using neighbors' advertised distances. And constraint systems — task scheduling with "x must start ≥ 3 after y" difference constraints — reduce to shortest paths where negative weights are the norm and a negative cycle means the constraints contradict each other.

The details (open as much as you like)

Why exactly |V| − 1 rounds suffice

Induction on path length: after round k, every node whose shortest path uses ≤ k edges holds its true price. Round 1 fixes all one-edge paths (the start's neighbors, via direct edges). If the claim holds for k, take any node whose shortest path uses k+1 edges; its predecessor on that path is correct after round k, and round k+1 relaxes the final edge — done. A simple path visits each node at most once, so no shortest path (absent negative cycles) needs more than |V|−1 edges. The early-exit in the code — stop when a full sweep changes nothing — is why real inputs usually finish in far fewer rounds than the worst case.

Dijkstra vs Bellman-Ford — the honest decision table

All weights ≥ 0: Dijkstra, no contest — O((|V|+|E|) log |V|) beats O(|V|·|E|) badly at scale. Any negative edge: Bellman-Ford (or a reweighting trick — Johnson's algorithm runs one Bellman-Ford to shift weights non-negative, then Dijkstra from every node; the next page's alternative for all-pairs). Need to detect negative cycles: Bellman-Ford is the tool, full stop. Distributed setting where nodes only know their neighbors: Bellman-Ford's relax-everything structure is the one that decomposes — which is why routing history went through it.

The code

// The demo's exact code (assets/js/algo/graphs.js), events elided:
function bellmanFord(graph, start) {
  const dist = new Map(graph.nodes.map((n) => [n.id, Infinity]));
  dist.set(start, 0);
  for (let round = 1; round < graph.nodes.length; round++) {
    let changed = false;
    for (const { u, v, w } of edges) {          // ALL edges, every round
      if (dist.get(u) === Infinity) continue;
      const alt = dist.get(u) + w;
      if (alt < dist.get(v)) { dist.set(v, alt); changed = true; }
    }
    if (!changed) break;                        // stable early — done
  }
  for (const { u, v, w } of edges) {            // the tripwire round
    if (dist.get(u) !== Infinity && dist.get(u) + w < dist.get(v)) {
      return { negativeCycle: true };           // "shortest" is undefined here
    }
  }
  return { dist };
}
