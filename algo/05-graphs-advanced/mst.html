Minimum spanning trees: connect everything, cheapest

Wire every node together — all connected, no waste — for the least total cost. Two famous algorithms solve it, both greedy, both provably perfect, and they don't even agree on tactics: one hoards cheap edges globally, the other grows a single tree outward. Both are justified by one lemma worth knowing by name.

Before you start Trees and cycles (a spanning tree has exactly |V|−1 edges) and union-find — its starring role arrives on this page.

The idea

A spanning tree keeps everything connected with the fewest possible edges — |V|−1, zero cycles, remove any edge and it splits. The minimum spanning tree minimizes total edge weight among all spanning trees.

Kruskal: sort all edges by weight; take each cheapest edge unless it would close a cycle. "Would close a cycle" = "its endpoints are already connected" — a union-find question, answered in near-constant time. Prim: plant a seed node; repeatedly add the cheapest edge crossing from the tree to a non-tree node — Dijkstra's shape with the priority "cheapest crossing edge" instead of "cheapest total path". Both are greedy with zero lookahead; the cut property below is why neither ever regrets a choice.

Where you'll meet this

The literal one: physical network design — fiber, power grids, pipelines — is where the problem was born (Borůvka, 1926, electrifying Moravia). The structural ones: single-linkage hierarchical clustering IS Kruskal stopped early (the fragments before the final merges are your clusters — used on embedding spaces in ML pipelines); image segmentation over pixel-similarity graphs; approximation algorithms (unit 11's TSP 2-approximation walks an MST); and network protocols computing loop-free topologies (spanning tree protocol in switches — same tree, different objective).

The details (open as much as you like)

Show the proof — the cut property

Lemma: split the nodes into any two non-empty sides (a cut). The cheapest edge crossing the cut belongs to some MST. Exchange argument: take an MST T that skips the cheapest crossing edge e. T is connected, so it crosses the cut somewhere — say edge f, with w(f) ≥ w(e). Adding e to T closes a cycle, and that cycle must cross the cut an even number of times, so it contains f. Swap: T − f + e is still a spanning tree (same edge count, still connected) and costs no more. So there's an MST containing e. ∎

Both algorithms are machines for applying this lemma. Kruskal's accepted edge is the cheapest crossing the cut "its fragment vs the rest"; Prim's is the cheapest crossing "tree vs not-yet-tree". Every greedy step is licensed by the same one-line exchange — which is the template for greedy proofs generally, formalized in unit 6.

Costs, and which to reach for

Kruskal: sorting dominates — O(|E| log |E|), then near-free union-find. Prim with a heap: O(|E| log |V|) — effectively the same class. Practical tiebreakers: Kruskal wants the edge list and nothing else (great for sparse graphs and streaming edges by weight); Prim wants adjacency and shines dense or when you need a tree grown from a specific seed. Uniqueness footnote: distinct edge weights ⇒ exactly one MST; ties ⇒ possibly many MSTs, all with the same total — the demos' agreement on 23 is guaranteed, their edge lists needn't be.

The code

// The demos' exact code (assets/js/algo/graphs.js), events elided:
function kruskal(graph) {
  const edges = [...graph.edges].sort((a, b) => a.w - b.w);
  const dsu = makeUnionFind(graph.nodes);        // unit 2, reporting for duty
  const tree = [];
  for (const e of edges) {
    if (dsu.find(e.u) === dsu.find(e.v)) continue;  // would close a cycle
    dsu.union(e.u, e.v);
    tree.push(e);                                // cheapest crossing its cut
    if (tree.length === graph.nodes.length - 1) break;
  }
  return tree;
}

function prim(graph, start) {
  const inTree = new Set([start]);
  const tree = [];
  while (inTree.size < graph.nodes.length) {
    const e = cheapestEdgeLeaving(inTree);       // heap-backed in production
    inTree.add(e.v);
    tree.push(e);                                // cheapest crossing THE cut
  }
  return tree;
}
