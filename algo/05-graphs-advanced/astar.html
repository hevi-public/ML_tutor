A*: search that knows where it's going

BFS and Dijkstra explore in all directions equally — half their work is spent walking away from the goal. A* adds one number per node: an optimistic guess of the remaining distance. Order the frontier by spent + guessed, and the search leans toward the goal — provably still finding the shortest path, as long as the guess never overpromises.

Before you start Dijkstra (A* is Dijkstra plus a compass) and the maze from unit 4 — the exact maze returns, this time raced.

The idea

Dijkstra orders its frontier by g(v) — the cost spent getting to v. A* orders it by f(v) = g(v) + h(v), where h(v) is a heuristic: a cheap-to-compute estimate of the cost still to go. On a grid, straight-line or Manhattan distance ("ignoring all walls, how far is the goal?") is the classic choice. Nodes that head away from the goal see their f explode and sink in the priority queue — they're simply never reached for expansion.

The one rule: h must be admissible — never an overestimate of the true remaining cost. Optimism is safe: a node can look more promising than it is and merely waste a bit of exploration. But a pessimistic h can make the true best route look bad enough that A* finishes without ever trying it — returning a wrong "shortest" path. Manhattan distance ignores walls, so it can only under-guess: admissible. And h ≡ 0 is admissible too — that's literally Dijkstra. A* is a family with Dijkstra at the cautious end and the quality of your guess as the dial.

Where you'll meet this

Game pathfinding is A*'s kingdom — practically every unit that walks across a map in every strategy game. Robotics motion planning; road navigation (with heuristics tuned by precomputation); puzzle solvers, where h = "how disordered is this state?". The deeper export is the pattern: best-first search under an optimistic bound is also branch-and-bound in optimizers and the shape of unit 9's beam search — which is A*'s reckless cousin: it keeps only the top-k frontier, trading the optimality guarantee for a memory budget, exactly the trade LLM decoding makes.

The details (open as much as you like)

Show the proof sketch — why admissible h can't break correctness

Suppose A* pops the goal with cost C while some route with true cost C* < C is still unfinished. That route has a frontier node y on it, with g(y) = its true prefix cost. Then f(y) = g(y) + h(y) ≤ g(y) + (true remaining from y) = C* < C = f(goal) — using admissibility in the "≤". So y would have been popped before the goal. Contradiction: when the goal is popped, nothing cheaper is pending. The proof is Dijkstra's argument wearing glasses: optimism keeps every truly-good route's f below any premature answer, so it can't be starved.

The efficiency dial: the closer h is to the truth (while staying under it), the fewer nodes have small enough f to bother expanding. h ≡ 0 explores like Dijkstra; h = exact remaining cost walks straight to the goal touching almost nothing.

The code

// The demo's exact code (assets/js/algo/maze.js), events elided.
// Diff from Dijkstra: ONE line — the frontier's sort key.
const h = (x, y) => Math.abs(gx - x) + Math.abs(gy - y);  // Manhattan: admissible

while (open.length) {
  const [x, y] = extractMin(open);       // min f = g + h   (Dijkstra: min g)
  if (isGoal(x, y)) return reconstruct(parent);
  for (const [nx, ny] of neighbors(maze, x, y)) {
    const alt = g.get(key(x, y)) + 1;
    if (alt < (g.get(key(nx, ny)) ?? Infinity)) {
      g.set(key(nx, ny), alt);
      parent.set(key(nx, ny), key(x, y));
      open.push([[nx, ny], alt + h(nx, ny)]);   // spent + optimistic guess
    }
  }
}
