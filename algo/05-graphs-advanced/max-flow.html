Max flow, min cut: how much can the network carry?

Edges get capacities — liters per second, requests per minute — and the question flips from "cheapest path" to "maximum throughput from source to sink". The algorithm is almost naive: find a path with spare capacity, push what fits, repeat. One idea rescues it from wrong answers, and the stopping condition turns out to be a theorem about bottlenecks.

Before you start BFS — it's the path-finder inside — and directed graphs generally. This is the unit's most different-feeling page; give it its own sitting.

The idea

A flow assigns each edge a throughput ≤ its capacity, with everything entering a middle node also leaving it (conservation — no node hoards). The obvious loop — find a source-to-sink path with spare capacity (an augmenting path), push its bottleneck amount, subtract — can paint itself into a corner: an early path may use an edge the optimal solution needs differently, and greedily-placed flow never moves.

The fix is the residual graph: after pushing f units along edge u→v, add a reverse edge v→u with capacity f. Pushing along a reverse edge means canceling earlier flow — rerouting it — so no decision is ever final. Search for augmenting paths in the residual graph and the corner disappears. Edmonds-Karp pins the path search to BFS (fewest edges), which caps the rounds at O(|V|·|E|) and makes the whole thing O(|V|·|E|²) — comfortably enough for graphs that fit on a screen.

Where you'll meet this

Capacity questions wear many masks: traffic engineering and bandwidth allocation; airline and crew scheduling; supply chains; image segmentation (graph cuts — the min cut IS the object boundary, a workhorse of classical vision); organ-donor exchange matching; project selection with prerequisites. The min-cut side answers reliability: "which set of links, if severed, disconnects us, and how small can it be?" — network robustness in one number. The details (open as much as you like)

Show the proof idea — max-flow = min-cut

A cut here: any split of the nodes with s on one side, t on the other; its capacity is the total of forward edges crossing it. Every flow ≤ every cut (all throughput must cross the line, and the line only carries its capacity) — so max-flow ≤ min-cut. Now run the algorithm to its stop: no augmenting path exists. Let S = everything BFS can still reach from s in the residual graph. Every original edge leaving S must be saturated (else its target would be reachable) and every edge into S carries zero (else its reverse-residual would open a way out). So the flow crossing the (S, rest) cut equals that cut's full capacity — the inequality is tight. The flow is maximum, that cut is minimum, and the algorithm's stopping state hands you both. ∎

In plain English: when you can't push any more, the network shows you exactly where its bottleneck line is. The theorem (Ford-Fulkerson, 1956) is one of the great duality results — the same pattern as "sorting's lower bound": an algorithm and an impossibility meeting at the same number.

Beyond Edmonds-Karp — honestly

This course runs Edmonds-Karp because every step fits on screen. Production flow solvers are cleverer: Dinic's algorithm batches BFS layers and pushes blocking flows for O(|V|²|E|), much faster in practice; push-relabel methods drop the path metaphor entirely, letting nodes hold temporary excess and shove it downhill — O(|V|²√|E|) variants dominate benchmarks. Neither is animated here; both are described faithfully in CLRS ch. 24/26 territory (see further reading). The residual-graph idea is the part they all share and the part worth owning.

The code

// The demo's exact code (assets/js/algo/graphs.js), events elided:
function maxFlow(graph, source, sink) {
  // cap[u][v] = residual capacity; reverse edges start at 0
  let flow = 0;
  for (;;) {
    const parent = bfsPath(cap, source, sink);   // shortest augmenting path
    if (!parent) break;                          // none left: DONE (min cut found)
    let bottleneck = Infinity;                   // tightest pipe on the path
    for (let v = sink; v !== source; v = parent.get(v))
      bottleneck = Math.min(bottleneck, cap[parent.get(v)][v]);
    for (let v = sink; v !== source; v = parent.get(v)) {
      const u = parent.get(v);
      cap[u][v] -= bottleneck;                   // consume forward capacity
      cap[v][u] += bottleneck;                   // open the undo edge
    }
    flow += bottleneck;
  }
  return flow;
}
