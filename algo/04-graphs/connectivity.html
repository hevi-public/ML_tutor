Connected components: how many islands?

The bluntest structural question a graph can be asked — which nodes can reach which at all? — and the gentlest algorithm in the unit: run any traversal, and when it runs dry, start another one somewhere fresh. Each launch discovers exactly one island.

Before you start BFS or DFS — either works; components only care that a traversal finds everything reachable.

The idea

In an undirected graph, "u can reach v" is an equivalence: it's reflexive, symmetric, and transitive. Equivalences partition — so the graph splits cleanly into connected components, maximal groups where everyone reaches everyone. The algorithm writes itself: sweep the node list; every time you meet a node no traversal has touched yet, launch a fresh traversal from it and label everything it reaches with a new component number. The outer sweep plus all the traversals together still touch each node and edge once — O(|V| + |E|) for the complete partition.

One subtlety worth naming: this page's method is a batch answer. If edges arrive over time and you must answer "same component?" between insertions, re-running a traversal per query is wasteful — that streaming version is exactly what unit 2's union-find was built for. Batch: traverse. Incremental: union-find. Knowing which regime you're in is the engineering skill.

Where you'll meet this

Network partition detection ("is the cluster split-brained?"); social and interaction graphs (communities before any fancy clustering); image processing, where flood fill IS component labeling on the pixel grid; fraud and entity resolution — records sharing a phone/device/address form components that are probably one actor; data lineage ("which tables are even connected to this report?"). In knowledge-graph pipelines, component analysis is a standard sanity check: a giant component plus debris is healthy, a thousand fragments means your entity linking is failing.

The details (open as much as you like)

Directed graphs break "connected" into two words

With arrows, reachability loses symmetry: u may reach v while v can't answer back. So directed graphs get two notions. Weakly connected: connected if you ignore the arrows — cheap, often what "is this one system?" means. Strongly connected: u reaches v and v reaches u — mutual reachability, a much stronger claim, and finding those components takes a genuinely cleverer algorithm (Tarjan's, unit 5). The microservices version: weak = "these services are wired together"; strong = "these services form a call cycle" — one is topology, the other is an architecture smell.

The code

// The demo's exact code (assets/js/algo/graphs.js), events elided:
function components(graph) {
  const adj = adjacency(graph);
  const seen = new Set();
  let comp = 0;
  for (const { id } of graph.nodes) {
    if (seen.has(id)) continue;        // already on some island
    comp++;                            // new island — launch a traversal
    const stack = [id];
    seen.add(id);
    while (stack.length) {
      const u = stack.pop();
      label(u, comp);                  // u belongs to island #comp
      for (const { to } of adj.get(u)) {
        if (!seen.has(to)) { seen.add(to); stack.push(to); }
      }
    }
  }
  return comp;
}
