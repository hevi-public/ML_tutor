Breadth-first search: explore in ripples

Drop a stone in a pond: the wave reaches everything one hop away, then everything two hops away, then three. That's the whole algorithm. It finds everything reachable, it finds shortest paths for free, it runs in O(|V| + |E|) — and it is quietly the most-executed graph algorithm in production software.

Before you start The graph model and unit 2's queue — BFS is what a queue is for.

The idea

Keep a to-do list of places to look next — the frontier. Start with just the source. Repeat: take the oldest entry off the frontier (a queue — first in, first out), look at its neighbors, and add any neighbor you've never seen before. The "never seen before" check is a set, and it's what stops a cycle from trapping you forever.

Because the frontier is a queue, you finish all the 1-hop nodes before touching any 2-hop node, all the 2-hop nodes before any 3-hop node — the ripple. That ordering is a theorem in disguise: the first time BFS reaches a node, it has arrived by a path with the fewest possible edges. Record who discovered whom and you get the actual shortest path, not just its length.

Where you'll meet this

Web crawlers expanding a frontier of URLs; "people you may know" (friends-of-friends is exactly the 2-hop ripple); garbage collectors marking every object reachable from the roots; network broadcast and peer discovery; shortest-hop routing; "blast radius" queries on a service mesh; knowledge-graph retrieval expanding n hops from the entities in a query (graph RAG, unit 9). And inside HNSW vector search, the candidate expansion at each layer is this exact loop with a similarity-ordered frontier. Learn this page and you've learned the skeleton of half of unit 9.

The details (open as much as you like)

Why O(|V| + |E|)?

The seen-set guarantees each node enters the queue at most once — so the loop body runs at most |V| times. When a node is processed, we scan its neighbor list; summed over all nodes, those scans touch each edge once per endpoint — O(|E|) total. In plain English: every node handled once, every edge glanced at a constant number of times. That's the canonical shape of a linear-time graph algorithm, and the counters above confirm it: visits ≤ nodes, checks ≤ 2·edges.

Show the proof — BFS finds shortest paths

Claim: when BFS first discovers node v, the discovery path has \delta(s, v) edges — the minimum possible. Induction on distance. Base: the source is discovered at distance 0. Step: assume every node at distance ≤ k is discovered with a correct, settled distance, and — the queue invariant — that the queue always holds nodes of distance k then k+1, never anything further apart. Any node v at distance k+1 has some neighbor u at distance k. When u is dequeued, v is either already discovered (at distance ≤ k+1, and it can't be less, since a shorter path to v would imply a neighbor of v at distance < k) or is discovered right now via u, at distance k+1. Either way v's recorded distance is exactly k+1, and it joins the queue after all distance-k nodes — preserving the invariant. ∎

The proof leans entirely on first-in-first-out. Swap the queue for a stack and the invariant collapses — that's the next page.

The code

// The demo's exact code (assets/js/algo/graphs.js), events elided:
function bfs(graph, start) {
  const adj = adjacency(graph);
  const seen = new Set([start]);
  const queue = [start];
  while (queue.length) {
    const u = queue.shift();          // oldest first — the ripple
    for (const { to } of adj.get(u)) {
      if (!seen.has(to)) {
        seen.add(to);                 // mark at DISCOVERY, not at visit —
        queue.push(to);               // or a node could be queued twice
      }
    }
  }
}
