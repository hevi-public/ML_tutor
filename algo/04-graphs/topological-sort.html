Topological sort: what order do things go in?

Given a pile of "X must happen before Y" constraints, find an order that respects all of them — or prove no such order exists. This is the algorithm inside every build system, package manager, migration runner and workflow engine you have ever used. It only works on a special kind of graph, and the failure case is as important as the success.

Before you start Directed graphs and DFS (for the second, layered derivation).

The idea

Model each task as a node and each "must come before" as a directed edge. If the constraints are satisfiable at all, the graph has no directed cycle — it's a DAG (directed acyclic graph), the single most important special case in this course. A topological order lists the nodes so every edge points forward in the list.

Kahn's algorithm finds one with an observation your intuition already uses: something with no prerequisites can go first. Count each node's incoming edges (in-degree). Repeatedly emit any node with in-degree 0, then delete its outgoing edges — which may free up new zero-in-degree nodes. If everything gets emitted: that's your order. If the loop stalls with nodes still un-emitted, every one of them is waiting on another — you've proven a cycle, with the stuck set as the witness. O(|V| + |E|), and the "ready set" is literally the work queue a parallel build scheduler would use.

Where you'll meet this

make, Bazel, Gradle, webpack — every build tool topologically sorts its target graph, and "cycle detected" in their error output is Kahn's stall. Package managers order installs with it; database migration runners order migrations; spreadsheets recompute cells in topo order of the formula graph. And it's foundational to LLM orchestration: agent frameworks (LangGraph-style pipelines, Airflow-style DAG runners) are topological sorts executing live — each step runs when its in-degree of unfinished dependencies hits zero, which is also exactly how parallel schedulers decide what can run concurrently.

The details (open as much as you like)

Why the stall proves a cycle

Suppose the loop stalls with a non-empty stuck set S. Every node in S has in-degree ≥ 1 counting only edges from S — anything it awaited outside S was already emitted and deleted. So walk backward from any stuck node: each step stays inside S, and since S is finite you must eventually revisit a node — that's a directed cycle. In plain English: if everyone left is waiting for someone else who's also left, the waiting is circular. This is precisely how deadlock detectors reason about "who holds what lock".

The DFS derivation, and how many orders exist

The previous page's exit times give a second algorithm: run DFS over the whole graph and emit nodes in reverse order of finishing. A node only finishes after everything reachable from it has finished, so all its dependents land later in the output — a valid topological order, also O(|V| + |E|). Kahn's is taught here because its intermediate state (the ready set) is visible and means something operationally; the DFS version shines when you're already doing DFS for other reasons.

Topological orders are almost never unique — any moment the ready set holds k nodes, k different valid continuations exist. That freedom is the parallelism a build scheduler exploits: the whole ready set can run simultaneously. The number of valid orders can be exponential; asking for "the" order is asking the wrong question.

The code

// The demo's exact code (assets/js/algo/graphs.js), events elided:
function topoSort(graph) {
  const adj = adjacency(graph);
  const indeg = new Map(graph.nodes.map((n) => [n.id, 0]));
  for (const e of graph.edges) indeg.set(e.v, indeg.get(e.v) + 1);

  const ready = [...indeg.keys()].filter((id) => indeg.get(id) === 0);
  const order = [];
  while (ready.length) {
    const u = ready.shift();                 // any ready node works
    order.push(u);
    for (const { to } of adj.get(u)) {       // "delete" u's out-edges
      indeg.set(to, indeg.get(to) - 1);
      if (indeg.get(to) === 0) ready.push(to);
    }
  }
  if (order.length < graph.nodes.length) return null;  // cycle! the rest are stuck
  return order;
}
