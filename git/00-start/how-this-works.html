How this tutor works

Every exercise on this site runs against a real git repository in your browser. Nothing is simulated, and nothing you type can hurt anything.

Before you start You've used git — you commit, branch, push, and you've googled your way out of at least one mess. That's the level this course starts from. It spends its time on the half of git that most people never get taught: rewriting history on purpose, the object database underneath, digging through the past, and the collaboration commands that stop you losing other people's work.

The idea

The awkward thing about learning advanced git is that the interesting commands are the frightening ones. Nobody wants to practise rebase --onto on the repository they get paid to look after, so most people learn these commands the hard way — at 6pm, on a branch that matters, from a Stack Overflow answer written in 2013.

So this site gives you a repository to break instead. Each page comes with a sandbox: a small history, already committed, with a prompt attached. You type real git commands, they really run, and the graph beside them really moves. When you wreck it, a button puts it back.

It really is git

That claim is worth being precise about, because a fake would teach you wrong. The engine here is isomorphic-git, a full reimplementation of git in JavaScript, writing to a filesystem that lives in your browser's storage. It writes real objects, hashed with SHA-1 exactly as git hashes them, into real .git/objects/ directories, with real refs in .git/refs/.

The proof is in the repository this site is built from: scripts/verify-fixtures.js builds every sandbox history with this engine, then hands the result to the actual git binary. Real git runs fsck --strict over it, agrees on every ref, and — given the same author and timestamps — produces the same commit, tree and blob ids. The object ids you're about to see are the ids git would have made.

Where the tutor adds its own code, and why that matters

isomorphic-git stops short of several commands this course is largely about: it has no reset, revert, rebase, bisect, reflog or fsck. Those are implemented in this tutor's own layer, on top of the same real plumbing — a rebase here builds genuine commit objects and moves genuine refs, and git reflog parses a real .git/logs/HEAD file that this engine wrote in git's format.

Two consequences you should know about, since a tutor that hides its seams is a tutor you can't trust:

  • Nothing is ever packed. Every object stays loose, so git gc isn't available. That's honest about a real consequence: in this sandbox, "lost" objects never actually get collected. The gc page covers what would happen on your machine.
  • There is no network. A static site has no server to clone from, so remotes are a second repository next door on the same filesystem, and fetch/push copy objects between them under git's real fast-forward and lease rules. Everything about refspecs and --force-with-lease works; the wire protocol is the part you don't get.

Anything else the sandbox can't do says so when you type it, by name. It will never quietly pretend a command worked.

Try it

Here's a sandbox with five commits in it. Try the four commands below — or anything else you fancy; git help lists what this prompt understands, and Tab completes commands, branches and filenames.

  • git log --oneline — the history you've been given
  • git cat-file -p HEAD — the actual bytes of the latest commit
  • echo "a change" >> README.md then git status
  • git commit -am "My first sandbox commit" — watch the graph move

Progress is kept in your browser only, and the sandbox keeps whatever state you left it in, so you can walk away mid-rebase and come back to it.

Two housekeeping notes

The sandbox needs your browser's storage, which browsers refuse to pages opened directly off disk. If a page says so, serve the site instead (npm run dev:git) and it comes alive.

Every sandbox is separate and disposable. Reset sandbox rebuilds this page's repository from scratch — the fastest way out of a mess, and the reason you should feel free to make one.
