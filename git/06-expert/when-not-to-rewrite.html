When not to rewrite

The judgement half of this course. Every tool in Unit 2 has a blast radius, and choosing well is mostly about who else is holding the commits.

The idea

You can now rewrite history several ways. The remaining skill is knowing when the cheaper, additive option is the right one — because a rewrite's cost isn't paid by you, it's paid by whoever already has the commits.

One question decides most cases:

The question Does anyone else have these commits? If no: rewrite freely, it's free. If yes: the rewrite costs every one of them a recovery procedure, so it needs to be worth that, and it needs to be announced.
Local, unpushedRewrite. amend, rebase -i, reorder, drop. No cost to anyone.
Pushed, your branch aloneRewrite, then push --force-with-lease. Standard practice on a pull request branch.
Pushed, others are on itOnly after telling them, with the exact commands they'll need. Consider whether a follow-up commit would do instead.
main, or any long-lived branchDon't. revert gets the same outcome additively.
A leaked secretRotate the credential first. Then rewrite if you like — but the secret is already out, and the rewrite is hygiene, not containment.

The habits worth keeping

Six things that between them prevent most of the situations this course teaches you to escape from:

  • Commit small and often; tidy before you push. The --fixup + --autosquash loop makes this nearly free, and it moves all your rewriting to before anyone else is affected.
  • Never type --force. Alias it: git config --global alias.pushf "push --force-with-lease".
  • Set the safe defaults once. pull.ff=only, fetch.prune=true, rerere.enabled=true, rebase.autoSquash=true. Four lines that remove four recurring annoyances.
  • Read the error. Git's rejections are unusually informative — "non-fast-forward", "stale info", "would be overwritten by checkout" each name the exact problem.
  • Check before you rewrite. git log --oneline <upstream>..<branch> shows exactly what a rebase will touch.
  • Copy the directory before anything frightening. The reflog covers nearly everything, and it is not a backup.

What you can now do

Working backwards through the course:

  • Read any object in a repository, and build a commit out of plumbing — so nothing git does is opaque any more.
  • Rewrite history deliberately: amend, reset, cherry-pick, rebase, --onto, autosquash — and undo any of it from the reflog.
  • Investigate: bisect a regression, blame through a refactor, find where a string entered the history, and recover work nothing points at.
  • Collaborate without damage: refspecs, leases, merge strategies, hooks, and the two ways to depend on another repository.
